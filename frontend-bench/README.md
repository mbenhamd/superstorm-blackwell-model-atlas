# Bench Console

An interactive console for LLM-serving benchmarks on the NVIDIA B300, deployed through KServe with vLLM or SGLang as the engine. It carries only real, traceable data:

- **Research atlas** (pinned commit, `src/data/atlas.json`): 12 models, 34 published weight exports (plus 3 requested exports with no Hub artifact, shown as "No artifact") and 54 B300 configurations with their exact engine arguments, configured engine release (separate from the latest release recheck), status, reconciliation notes and source IDs.
- **Hugging Face**: every model and export pinned to an immutable revision; benchmark tables extracted verbatim from the pinned cards (`data/hf-card-benchmarks.json`).
- **Artificial Analysis**: Intelligence Index v5.0.1, model level, per effort variant and component.

Bench results (GuideLLM sweeps) are **not connected yet**. Throughput and latency fields stay empty (“—”) rather than estimated; they fill in from imported runs (`bun run import:runs`) or a PostgreSQL store with the bench schema.

The visual system adapts the public Linear DESIGN.md analysis (one lavender accent, surface ladder, hairlines) on React + Tailwind v4 + shadcn/ui + dashboardcn. See [DESIGN.md](DESIGN.md), [ADR 0005](docs/adr/0005-react-shadcn-dashboardcn.md) and [ADR 0006](docs/adr/0006-real-catalog-data.md).

## Open it

- **Offline:** open `preview.html` (generated by `bun run build`) in a modern browser. App, styles and the pinned atlas snapshot are inlined; no server, network or fonts required.
- **Local server:** `bun install && bun run dev`, then http://127.0.0.1:3000.
- **Static host:** see [Static deploy](#static-deploy).

Theme and experiment plans persist in `localStorage` under `bench-console-v1` when storage is available. Refresh the snapshot from the parent atlas with `bun run import:atlas` (`--check` verifies it matches).

## Static deploy

The static build is `public/` (`index.html`, `assets/app.js`, `assets/styles.css`, `_headers`). It runs in offline mode (`<meta name="bench-mode" content="offline">`): no API, no database, no runs; planning cards and theme stay in the viewer's browser storage. It may be hosted publicly (see [SECURITY.md](SECURITY.md)).

| Setting | Value |
| --- | --- |
| Build command | `bun install --frozen-lockfile && bun run build` |
| Output directory | `public` (`public/assets/` is git-ignored, so the host must build) |
| Bun version | 1.4.0 (on Cloudflare Pages: environment variable `BUN_VERSION=1.4.0`) |
| Routing | hash routes; no SPA fallback needed |
| Data | the committed `src/data/atlas.json`; do not run `import:atlas` on the host (it needs the parent repository) |
| Headers | `public/_headers` mirrors the API server's CSP, `X-Frame-Options: DENY`, `nosniff` and `Referrer-Policy: same-origin`; the build rewrites only `public/index.html` and `public/assets/`, so it survives |

Without a host that reads `_headers`, the page is served without these headers.

| Thing | Form | Example |
| --- | --- | --- |
| Display name | `Model · Export · Engine · TPn[ · DPm][ · Knob]` | GLM 5.3 · NVFP4 · RedHatAI · vLLM · TP8 |
| Export | `Native <format>` for the publisher's own quantized release, else the precision class, plus a third-party exporter | Native MXFP4; NVFP4 · NVIDIA |

| Hardware label | `<max_system_replicas>x<num_gpus><gpu_type>` from the run; the GPU count is omitted when it is 1. Reading `num_gpus` as GPUs per replica is an assumption, not confirmed at source; runs with more than one replica show "GPU divisor unconfirmed" | `1xB300`, `1x2B300`, `2x8B300` |

## Information architecture

Sidebar labels: TL;DR, Intelligence, Throughput, Compare, Engine, Models, Deployments, New benchmark, plus Methodology.

| Route | Purpose |
| --- | --- |
| `#/tldr` | Pick a model (`model`), GPU shape (`shape`, all by default) and sort (`sort`: sustainable, cmax, name); the workload and SLO come from the top bar. Setups table, always expanded and grouped by weights export: every setup ranked by sustainable tok/min/GPU with a bar scaled to the best, Δ vs best (±3 % = tie, assumed policy), C_max, TTFT/ITL p95 at C_max, latest run with incomplete/errored counts, and compare / evidence / Throughput actions; unmeasured setups listed last with "—"; when no setup is measured on the dataset the metric columns collapse into one "Metrics · not measured" column. Champions by workload: per dataset the best setup and its challengers with Δ vs champion (a selected row sets the top-bar workload); with no run of the model × shape it is one compact block of selectable workloads. No Artificial Analysis element |
| `#/intelligence` | AA v5.0.1 by effort variant, AA index vs active parameters, context and scale, component heatmap (unscored models keep their published cells, missing cells hatched), what each benchmark measures; the serving frontier appears once bench results exist |
| `#/throughput` | Selector row: Base model · Runtime (engine and configured build) · Hardware (GPUs and parallel shape) · Runtime config (this model's setups for that runtime and hardware, grouped by weights export; each option lists knob chips, run count and sustainable tok/min/GPU or "not measured") · Run (date · dataset, shown when the configuration has a run); visible Workloads and Add to compare buttons in the page header. ## Commands

```sh
bun install
bun run typecheck          # tsc for server/domain and client projects
bun run test:unit          # domain, engine, repository, runs, chart-scale and picker-search tests
bun run build              # public/ and offline preview.html
bun run browser:install    # Playwright Chromium, once
bun run test:browser       # requires a fresh build
bun run screenshots        # writes to $SCREENSHOT_DIR, outside the repository
bun run design:lint        # @google/design.md lint
bun run quality            # typecheck + unit tests + build
```

PostgreSQL: `bun run db:up && bun run db:migrate && bun run db:seed`, then `bun run dev`. `db:migrate` applies every `db/NNN_*.sql` in order (checksummed, append-only); `db:seed` upserts the pinned model cards and atlas commit from `src/data/atlas.json` and seeds no runs. Measurements enter only through `bun run import:runs <file.json> [--dry-run] [--replace-older] [--dataset-map=<map.json>]` (`--dataset-map`, or `DATASET_MAP=<map.json>` with `RUNS_FILE`, renames datasets from a local JSON object of old → new names before matching; runs exported by the execution repository; one `experiments` row per seven-column identity, its `metrics` replaced on re-import). Without PostgreSQL, `RUNS_FILE=<file.json>` loads a validated runs file into the memory store; `tests/fixtures/sample-runs.json` is TEST data for automated tests only. Integration tests: set `TEST_DATABASE_URL` to an isolated, migrated and seeded database and run `bun run test:postgres`.

## Scientific invariants

- Missing values render as "—"; zero is an observed value. Nothing is filled from a neighbouring model, variant or export.
- A level is inside the SLO when TTFT p95 ≤ prompt tokens ÷ prefill speed, ITL p95 ≤ the ceiling and success ≥ 99 % (the success floor is a console rule; the SLO presets define only prefill speed and ITL). Prompt tokens per level = input tok/s ÷ requests/s. C_max is the last passing level. No interpolation.
- Sustainable throughput = **total (input + output) tok/s at C_max × margin × 60 ÷ GPUs**, in tok/min/GPU; it ranks configurations and draws the frontier. The GPU divisor is the run's `num_gpus` (falling back to the catalog shape only when no run exists); a run whose `num_gpus` differs from the catalog shape is flagged `topologyMismatch`. This is the console's definition; the numerator, rate window and handling of incomplete requests are assumed and not confirmed at source. The divisor assumes `num_gpus` counts GPUs per replica; if a multi-replica run's throughput is aggregated over replicas, tok/min/GPU is overstated by the replica factor, so such runs are flagged "GPU divisor unconfirmed" (the formula is unchanged). The output-only figure (`sustainableOutputTpmPerGpu`) and the legacy output tok/s/GPU × margin (`capacityTpsPerGpu`) are kept beside it. Deployment-wide = the same rates × margin × 60 without the GPU division, split into input and output.
- The nominal TTFT ceiling (input budget ÷ prefill speed) is defined only for single-turn datasets without shared prefixes; multi-turn and shared-prefix datasets derive it per level from measured prompt tokens.
- Two values within ±3 % of the larger one read "tie" (assumed single-run noise; policy, unverified).
- Run files with `"_test"` entries are TEST fixtures: the console shows a persistent "TEST DATA — invented values" banner, exports are labelled TEST DATA, and `import:runs` refuses to write them to PostgreSQL (`--dry-run` still validates them).
- The AA index is model level. It is shown beside any configuration as "AA (model)" and enters the serving frontier only for the publisher's own export; it never transfers to a third-party quantized export.
- HF card tables are publisher or exporter claims at their stated settings; Δ is calculated only when the card names a baseline column.
- Serve commands reproduce the configured engine arguments exactly, one flag per line; KServe runs them as the container command.
- The engine build shown for a configuration is its configured release (`engine_release`, e.g. vLLM v0.31.0), or "source snapshot" when only a reviewed source commit is recorded, or "unreleased build". The latest release recheck (e.g. v0.33.0) is shown separately as "Rechecked … · arguments not revalidated" with its required reconciliation items; it is never presented as the build or as tested. `tested_on_target: false` reads "Not tested on B300".
- Experiment status changes are planning records; nothing is launched.
