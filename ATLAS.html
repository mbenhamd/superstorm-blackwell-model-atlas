START_HERE.md

Start here: a model-serving factory

You do not need to know GPU programming to navigate this repository. The core distinction is the model is the trained machine; the engine operates it; the platform keeps the service available.

One request, from question to answer

A tokenizer turns text into numbered pieces called tokens. An embedding turns each number into a vector, a list of numerical features. The model repeatedly transforms those features through its layers. Attention retrieves useful information from earlier tokens. A feed-forward block performs another learned transformation. A final head produces scores for possible next tokens, and the sampler chooses a token. This repeats until a stopping condition is met. Images require an additional encoder and preprocessing path. The exact implementation varies across the eight model reports. qwen3.8-27b-CARD gemma-4-31b-it-CFG mistral-medium-3.5-CFG

Prefill is reading the question and existing conversation. Decode is writing the answer a piece at a time. A restaurant analogy helps: preparing all ingredients is not the same job as plating each course. An optimization that speeds preparation might slow service if it monopolizes the same kitchen.

Five objects that must not be confused

Object In this repository Analogy

Checkpoint A particular set of trained and possibly quantized weights The calibrated machine, not just its blueprint
vLLM / SGLang Scheduling, cache management and GPU execution Factory operating system

KServe Kubernetes resources, rollout and routing lifecycle Warehouse and dispatch management

KServe is not a third arithmetic engine competing with vLLM and SGLang. It can manage a service whose container runs one of them. Advanced LLM orchestration has its own resources and integration requirements. KS KSRT KSLLM

Dense versus mixture of experts

A dense model uses its ordinary feed-forward blocks for every token. An MoE model routes tokens through a selected subset of experts. A building with 896 specialist offices may consult only 16 offices for a token, but the others still occupy floor space. Activated parameters describe selected work; total resident parameters and tensor bytes describe weight storage. Do not buy GPU memory based only on the activated count. kimi-k3-CARD glm-5.3-flash-CARD

Four kinds of memory

Weights are the learned constants. KV cache stores attention information associated with previous tokens. Recurrent state is the running summary used by linear-attention blocks. Temporary memory includes activations, graph capture, communication buffers, quantization/repacking workspaces and speculative verification. A model can fit its weights and still fail to start or run long requests.

A notebook is a useful analogy for recurrent state, but it is not a lossless transcript. Full-attention or sparse-history layers remain important. Conversely, a small recurrent state can need several snapshots per request for prefix caching, overlap and speculative rollback. The per-sequence state matrix alone is not the complete state-pool allocation. qwen3.8-27b-GR kimi-k3-GR glm-5.3-flash-GR

What precision changes

BF16 uses 16 bits per represented element. FP8 usually uses eight. NVFP4 and MXFP4 use four-bit values plus different scaling structures. Think of recording measurements to different precision, with scale notes attached to groups of values. They are not interchangeable file extensions. Exported checkpoints frequently mix several precisions. NV4 TE CUDNN

What the evidence labels mean

Publisher fact means that a primary source states it. Config extraction means the value is present in the cited machine-readable configuration. Source inspected means particular code ranges were read at a named commit. Publisher benchmark means the author measured it under stated conditions. Derived means a calculation here uses explicit assumptions. Candidate means a setting needs testing. Not verified means no confirmation was obtained; it does not mean false.

Suggested workload portfolios

For short interactive chat, prioritize first-content latency and stable output pacing; include target-only baselines because drafting is not free. Hardware target: eight B300 GPUs per node

Verified hardware facts versus supplied inventory

NVIDIA documents a DGX B300 with eight B300 GPUs, 288 GB per GPU and approximately 2.3 TB aggregate GPU memory. Its CUDA GPU table identifies B300 as compute capability 10.3. Those are useful architectural references, but your supplied SXM6-AC label does not identify a complete DGX-equivalent bill of materials. CPU, RAM, NVMe, NICs, firmware, power and cooling remain OEM-specific until inventoried. HW CC

Eight times 288 is 2,304 advertised GB. If those units are interpreted as decimal bytes, that is approximately 2,145.77 GiB. Treat this as a unit-conversion illustration, not a prediction of nvidia-smi output: query the memory actually exposed by the driver and allocator. Neither advertised total nor driver-visible total is all available for weights.

Preflight before tuning

Run python scripts/preflight.py --output preflight.json on the actual inference host. It runs read-only version and topology queries; it does not set GPU clocks, power limits, MIG mode, network devices or kernel parameters. Confirm eight intended devices, compute capability, driver/CUDA compatibility, peer-access topology and process exclusivity. Record CPU architecture so x86_64 B300 and Grace-based GB300 software images are not confused.

Do not treat a workstation RTX Blackwell measurement as an HGX B300 measurement. SM12x devices, B300 SM10.3, and B200 SM10.0 have different kernel and topology requirements. Likewise, GB300’s host and memory architecture is not an automatic match for an x86 SXM node. CC qwen3.8-27b-GR deepseek-v4-flash-0731-VR

Capacity plan

Use this budget for each GPU:

weights and repacked weights
+ persistent attention/index caches
+ recurrent-state pools and snapshots
+ temporary prefill/decode activations
+ communication and graph buffers
+ explicit safety headroom
<= memory exposed to the process

Shard each term only across the process group that actually shards it. TP can shard heads or linears; EP distributes experts; DP may replicate attention; DCP partitions decode context. None is a universal divisor for the entire memory budget. kimi-k3-GR glm-5.3-flash-GR qwen3.8-27b-GR

Blackwell-specific optimization order

First establish an image that loads the correct artifact with finite, coherent outputs. Next verify kernel selection and mixed-format behavior. Only then compare FP8 versus NVFP4, attention backends, CUDA graph modes, batch caps, cache precision and speculative decoding. A newer kernel that is incompatible with block scales, SiTU or state replay can return incorrect results without an obvious crash. The Kimi fixes provide a concrete example. KIMIPR KIMIVPR GQUANT

Inspect whether time is spent in expert GEMMs, attention, routing, all-to-all, reductions, host scheduling, tokenization or memory movement. Changing a precision format cannot remove an unrelated queueing or network bottleneck. For low-concurrency dense models, launch and synchronization overhead can dominate; at longer contexts, cache bandwidth can dominate. This is a workload hypothesis to test with traces.

Scale overhead

For an ideal one-dimensional payload, MXFP4 with one byte of scale per 32 four-bit values consumes 0.5 + 1/32 = 0.53125 bytes per value. NVFP4 with one byte per 16 values consumes 0.5625 bytes per value before the outer tensor scale. These correspond to 4.25 and 4.5 effective bits for those parts. Real exports can add padding, layouts and mixed modules. NV4 TE4 CUDNN

For Qwen Flash Next, the 51B n-gram table is FP8 in the NVIDIA derivative, so its ideal payload alone is around 51 GB. Four-bit estimates that omit that table are fundamentally incomplete. qwen3.8-flash-next-NV

Uniform GQA cache

For an unpadded, non-shared cache with separate K and V:

KV bytes = 2 × layers × KV_heads × head_dim
           × tokens_per_sequence × concurrent_sequences × bytes_per_element

Use it only where those assumptions hold. Mistral’s published configuration gives an illustrative 88 GiB BF16 payload for one 262,144-token request. Qwen 27B’s 16 full-attention layers give 16 GiB at that length, plus its separate linear state. A factor-of-two precision change affects element payload, not necessarily every allocation. mistral-medium-3.5-CFG qwen3.8-27b-CFG

Do not apply this formula unchanged to Kimi MLA, DeepSeek compressed attention, GLM sparse indexers or Gemma’s heterogeneous local/global and key/value-sharing behavior. A head count in config is not an allocator specification. kimi-k3-CFG deepseek-v4-flash-0731-CFG gemma-4-31b-it-CFG

Recurrent state

A simple per-sequence matrix-state illustration is:

matrix bytes = linear_layers × value_heads × key_dim × value_dim × state_bytes

Under this explicit layout assumption and FP32 state, the matrix-only quantities are Kimi 414 MiB, GLM Flash 136 MiB, Qwen 27B 144 MiB and Qwen Flash Next 108 MiB. They exclude convolution, padding and extra state slots. The published Qwen cookbook’s fuller state-slot estimate is therefore larger than the bare matrix calculation. kimi-k3-CFG glm-5.3-flash-CFG qwen3.8-27b-CFG qwen3.8-flash-next-CFG qwen3.8-27b-GR

A state pool may reserve multiple slots per running request for prefix checkpoints, overlapping work and draft verification. The SGLang Qwen recipe distinguishes ordinary state slots from speculative intermediate buffers and replay-ring implementations. Use actual slot counts and boot logs; never multiply a generic “default concurrency” by only one matrix. qwen3.8-27b-GR

Practical capacity workflow

Measure post-load free memory, graph-capture peak, KV token capacity, state-slot capacity and maximum running requests separately. Increase request length with batch fixed, then batch with length fixed. Repeat after changing speculation, cache dtype or multimodal input shape. Leave a documented safety margin and test cancellation/eviction paths under load.

Run python scripts/memory.py --help for the tested analytic calculator. It refuses to present a universal hybrid-cache estimate and labels all numbers as payload estimates.

Precision, serialization and kernels

A precision name is not a deployment contract

Term Meaning Common mistake
BF16 16-bit floating representation with broad exponent range Calling dequantized FP4 weights the original BF16 model
FP8 Eight-bit floating family, often E4M3 for inference Ignoring block, channel, tensor and dynamic-activation schemes
MXFP8 Microscaled FP8 with shared block scale Treating it as the same packing as ordinary FP8
MXFP4 Four-bit values with microscaling, typically 32-value blocks Renaming it NVFP4
NVFP4 Four-bit values, 16-value scaling and outer scaling Assuming all tensors in an NVFP4 checkpoint are four-bit
W4A4 Four-bit weights and activations for the affected operators Assuming routers, KV cache and vision are also four-bit
W4A16 Four-bit weights with higher-precision activations Expecting the same compute path as W4A4
Weight-only FP8 Weights compressed; activation treatment is loader/kernel-specific Assuming its exporter label fixes runtime activation precision

The representations and scale distinctions are documented by NVIDIA. E2M1, E4M3 and E8M0 refer to exponent/mantissa layouts, not model sizes. NV4 TE TE4 CUDNN

Four layers of compatibility

Numeric format: bit layout, scale data types and granularity. Serialized representation: tensor names, packed shapes, exclusions, exporter metadata. Mathematical operator: activation, bias, normalization, router weighting, clamping and residual behavior. Runtime implementation: supported kernel, alignment, repacking, sharding and target GPU architecture.

A failure at any layer can break the result. In the inspected SGLang code, FP4 GEMM selects different W4A4 and W4A16 paths and checks whether FlashInfer functionality is available. Padding rules differ across kernel families. In the Kimi fixes, correct scale loading and SiTU activation behavior are as important as selecting four-bit matrix multiplication. GQUANT KIMIPR KIMIVPR

Exporter differences in this catalog

Kimi native MXFP4 is distinct from NVIDIA mixed NVFP4/FP8. RedHat GLM NVFP4 uses compressed-tensors for routed experts. NVIDIA Qwen 27B mixes NVFP4 MLP/head with FP8 attention. NVIDIA Flash Next additionally retains BF16 components and an FP8 n-gram table. RedHat Gemma excludes vision, embeddings and head from its Transformer-block quantization. Mistral uses a static-activation FP8 scheme. See each model’s precision.md for primary citations and exact artifact IDs; no universal NVFP4 loader flag is safe across this set.

FP8 KV is independent

Weight precision changes model operations. KV precision changes stored attention history. Recurrent-state precision changes an additional state representation. Test these separately: baseline weights + baseline cache; low-precision weights + unchanged cache; then lower-precision cache/state. Otherwise an accuracy difference cannot be assigned to its cause.

The SGLang Qwen recipe gives a concrete metadata trap: some derivative exports default auto KV to FP8, whereas NVIDIA’s export leaves it BF16 without an explicit setting. Matching command text with auto therefore does not necessarily match effective precision. qwen3.8-27b-GR

Why four-bit can win, and why it can lose

A lower-byte representation may reduce weight bandwidth and let a larger useful batch or cache fit. It can also introduce scale handling, conversion, padding, calibration error and backend constraints. At low concurrency, synchronization and launch overhead may dominate the saved arithmetic. At long context, attention-history traffic can dominate expert weights. These are reasons to measure, not reasons to reject quantization.

The decision metric is successful, quality-accepted work under a latency objective. A faster kernel with a regression in tool arguments or retrieval is not a production improvement. Publisher results can establish plausibility, but they do not certify your prompts, image distribution, sampling settings or software bill of materials.

Calibration and quality gates

Use a representative holdout with coding, tool use, instruction following, multilingual questions, long context and vision where supported. Freeze the tokenizer, chat serialization and reasoning effort. Include repeated seeds for stochastic tests and paired comparisons. Report absolute differences, sample sizes and uncertainty rather than only a rounded “recovery” percentage.

A native quantization-aware-trained release and a post-training quantized derivative are not the same intervention. Do not attribute the former’s quality to an exporter conversion that was never evaluated. kimi-k3-CARD qwen3.8-27b-NV glm-5.3-NV

vLLM, SGLang and KServe: justified roles

Decision

Use vLLM and SGLang as competing execution engines. Use KServe as the optional Kubernetes lifecycle layer. Begin with a single-node colocated prefill/decode service. Select an engine per exact artifact, not by brand loyalty. Introduce disaggregation when measured queueing and transfer economics justify it. KS KSRT KSLLM

Why vLLM is a strong first path here

The inspected registry resolves model classes to implementation modules, including current vllm.models.* namespaces for several newer architectures. Its Kimi DSpark implementation exposes model-specific MLA, draft quantization, hidden-state projection and fused reductions. Official recipes cover the requested families, and Mistral explicitly recommends vLLM. These are compatibility and reproducibility reasons, not a claim that it is always faster. VREG VDS mistral-medium-3.5-CARD

The exact NVIDIA Flash Next mixed export is documented for vLLM. Its MTP loader fix is merged; Kimi’s separate FP8-attention support PR remains open. Therefore two NVIDIA NVFP4 artifacts deserve different readiness labels even inside the same engine. qwen3.8-flash-next-NV QPR KIMIVPR

Why SGLang is a strong first path here

Its model-specific cookbooks make recurrent-state allocation, cache hierarchy and speculative strategy explicit. The current release includes hybrid-model and Kimi correctness/performance work. The Kimi mixed NVFP4/FP8 compatibility fix is merged, and its source handles multiple quantized GEMM pathways. These justify a first compatibility trial for Kimi NVFP4 and a serious comparison for GLM Flash and Qwen hybrid models. They do not substitute for B300 workload measurements. GREL GQUANT KIMIPR glm-5.3-flash-GR qwen3.8-27b-GR

The inspected SGLang registry can discover an architecture through package entry classes, log an import error, or append a Transformers fallback during normalization. This makes the resolved implementation and import logs important evidence. A registry match alone is weaker than a successful exact-artifact load with verified kernels. GREG

What KServe contributes

KServe adds declarative deployment, lifecycle reconciliation and integration with Kubernetes resources. Its LLMInferenceService path adds composable LLM configuration, specialized scheduling, distributed workloads and prefill/decode orchestration. Benchmark and correctness protocol

Define the decision before measuring

Choose a service-level objective and quality threshold. For example, compare request goodput while meeting a declared p95 first-token and generation-latency budget. Do not replace those budgets with convenient measured numbers after a run. Store the exact values in each experiment manifest; this atlas supplies no invented production SLA.

Compare engines on the same node, model revision, export, tokenizer, chat template, thinking mode, sampling, input/output lengths, concurrency, arrival process and cache state. A warm prefix hit against a cold-cache run is not a fair comparison. Weight precision, KV precision and recurrent-state precision must be recorded separately. Cap vision payloads and account for visual tokens rather than pretending an image is one text token.

Correctness gates before speed

First test target-only loading and finite outputs against the publisher/reference implementation. Cover ordinary chat, arithmetic, coding, multilingual requests, EOS/stop handling, JSON schemas, tool-call boundaries and image inputs where supported. Quantized checkpoints require a representative held-out quality evaluation, not only one coherent answer. Compare aggregate metrics and failure categories, not exact sampled strings.

Then test long contexts, repeated prefixes, cache eviction, cancellation, graph replay, batch size changes and partial failures. Hybrid models must preserve recurrent and convolutional state as well as token KV. For speculative decoding, verify that accepted and rejected branches commit or restore the right state. Use native acceptance; reject simulated-acceptance environment settings. Evaluate the same workloads with speculation disabled.

For 0731 DeepSeek use its encoding and DSpark contract, not a preview model's MTP invocation. For Kimi match the drafter to the engine and target. For Qwen Flash Next include PLE/ngram and draft tensors in load accounting. For Gemma verify no unsupported audio feature was accidentally enabled from a generic example.

Minimum experiment matrix

Run target-only first. Sweep input lengths 4K, 16K, 32K and 64K; extend to 128K and the native maximum only after capacity and accuracy gates pass. Sweep output lengths representative of the application, such as 128 and 1,024 tokens, plus the real trace. Include concurrency 1, 8, 32 and the point just before saturation. Repeat independent runs, randomize order and retain failures.

For dense Qwen/Gemma compare TP1 replicas with TP2/4 as total-node capacity, not only one process's throughput. For large MoE compare the documented TP/DP/EP topologies before introducing cross-node communication. For hybrid models sweep the state/KV pool split only with measured pool demand. For DSpark/MTP record acceptance, verification work and queueing at each load, not a single best batch-one speedup.

Metric definitions

TTFT is time from request submission to first generated semantic content. State whether reasoning or tool deltas count. First-answer latency excludes hidden/reasoning content and may be much larger. End-to-end latency includes the complete response. ITL requires reliable per-token emission timing: an SSE chunk can contain zero or several tokens, so chunk gaps are not automatically token latency.

TPOT is generation time per output token under an explicitly stated formula. A network-based approximation from first content to final event divided by completion_tokens−1 is a proxy, not a GPU-only measurement. Output throughput uses the total reported output-token count divided by full measurement wall time. Goodput counts only successful requests/tokens meeting the declared latency and quality objective. Report error rate, p50/p95/p99 and offered load; never drop failures from the denominator silently.

Natural acceptance is observed accepted draft work under the deployed sampling procedure. Define whether the length includes the extra target token. Memory includes resident weights, caches, recurrent state, graph capture, activations, workspaces and communication buffers. Keep physical/advertised GB and binary GiB explicit.

Included runner and its boundaries

run_streaming.py provides a lightweight, closed-loop, concurrent HTTP/SSE probe using the Python standard library. It records semantic deltas and usage when the endpoint supplies it. It does not infer tokens from chunk counts, execute returned tools/code, generate large synthetic prompts or supply an open-loop arrival process. Use the pinned engine's native benchmark harness for controlled token workloads and detailed kernel/service measurements, and compare against this client view.

python benchmarks/run_streaming.py --base-url http://127.0.0.1:8000 \

Qwen 3.8 27B: architecture

Data flow

Vision/text → [GDN → GDN → GDN → gated full attention] × 16, with dense MLPs → output head; optional MTP.

How the parts work together

Three Gated DeltaNet layers are followed by a gated full-attention layer, repeated through the text backbone. The linear-attention path maintains a recurrent matrix state with a short convolutional component. Full-attention layers retain ordinary token-history cache. Consequently, the model has both a context-dependent cache and a concurrency-dependent state pool.

The key and value head counts in the linear path differ. The full-attention path has its own query-head count, KV-head count and head dimension. Deriving head dimensions by dividing hidden width by a familiar head count would produce the wrong shapes here; use the explicit configuration.

The feed-forward network is dense, not MoE. Every token traverses those linears; there is no expert-parallel switch that turns it into a sparsely activated 27B model. The vision encoder is shared infrastructure for image/video inputs, with spatial merging and temporal patching before language processing.

MTP is an optional additional serving path. It changes scheduling and temporary-state needs, not the base model’s dense-versus-MoE identity. The official context extension beyond the native window is not evidence that every engine, quantization and workload preserves useful accuracy at that length.

Qwen 3.8 Flash Next: architecture

Data flow

Tokens → vocabulary + n-gram/PLE path → [GDN×3 → QSA] ×12 → gated residual streams + MoE → output; separately quantized MTP branch.

How the parts work together

The backbone combines three recurrent Gated DeltaNet layers with a sparse-attention layer in each four-layer group. The sparse indexer selects compressed blocks, so its 2,048-token budget corresponds to a different abstraction from a full context length. The output remains autoregressive even though much of the attention work is recurrent or sparse.

A large n-gram embedding table provides an additional lookup path for local token patterns. It changes the balance between arithmetic and table access. The PLE configuration identifies where that representation is injected; treating it as an ordinary vocabulary embedding or dropping it because it is not in the 125B headline would change the model.

The main MoE selects a small subset of many experts. Alongside it, gated low-rank residual streams preserve several information paths. The configuration field hc_count is not enough by itself to label this mechanism identical to DeepSeek’s or GLM’s manifold-constrained hyper-connections. Their actual mixing rules differ.

The MTP module and its own expert precision must be loaded independently of the main routed experts. A mixed quantization loader that assumes one algorithm for every expert layer can pass target-only tests yet fail as soon as speculative decoding is enabled.

Mistral Medium 3.5: architecture

Data flow

Text / Pixtral vision → projector → 88 dense GQA blocks with YaRN → output head → Mistral encoding/tool/reasoning protocol.

How the parts work together

The language network uses dense feed-forward blocks and grouped-query attention. Many query heads share a smaller set of key/value heads. Unlike the hybrid models in this catalog, its text configuration does not declare a sliding window; full token history therefore drives attention-cache growth across the language layers.

The positional configuration extends an original short window using YaRN parameters. A later corrected Transformers configuration is explicitly referenced by the publisher. A quantized derivative created before that correction can retain incorrect long-context behavior even when its weights are otherwise faithful.

The Pixtral vision encoder and multimodal projector process image inputs. Their precision exclusions are part of the official FP8 export, so the whole checkpoint is not homogeneous FP8. The text architecture class, vision architecture and tokenizer/encoding stack together define a valid model load.

The official repository contains both consolidated-format and Transformers-style weight shards. These are alternate representations, not six disjoint pieces of one larger model. Downloading both layouts approximately doubles storage and startup transfer without doubling the model’s capability.

Kimi K3: architecture

Data flow

Text / vision features → KDA or gated MLA → attention-residual mixing → dense or latent MoE → repeat → output head; optional DSpark proposes → target verifies → commit accepted state.

How the parts work together

The text backbone alternates frequent Kimi Delta Attention (KDA) updates with periodic gated multi-head latent attention (MLA). KDA carries a recurrent summary forward; the MLA layers retain access to token history through compressed attention representations. This combination makes the model neither ordinary full attention everywhere nor a constant-memory model everywhere. A long conversation still consumes token-cache memory in the MLA layers.

The feed-forward path is a latent mixture of experts. Routing selects specialists, but the specialist computation is represented in a narrower latent space rather than treating every expert as a full-width dense feed-forward network. The dense prefix, shared experts, routers, normalization, and residual machinery still perform work. The number of selected experts therefore does not by itself determine end-to-end FLOPs or latency.

The configuration also exposes block attention-residual organization. Do not substitute a plain residual-add implementation simply because tensor shapes happen to agree. Likewise, SiTU is not interchangeable with a default SwiGLU activation: the checkpoint-dependent activation and scaling must survive expert dispatch, quantization, fusion, and reduction.

Image or video processing adds a vision encoder and transport path before language inference. Its memory and CPU-transfer overhead must be budgeted separately from text tokens. A text-only benchmark does not certify multimodal throughput.

Why DCP8 does not divide all memory by eight

The SGLang cookbook describes a split between target MLA cache, recurrent KDA state and drafter cache. In its published sizing rule, target MLA token cache is divided by DCP, while the DSpark draft token cache remains replicated. Thus a small replicated cache can become significant after the larger target cache is sharded.

state_to_KV_pool_ratio =

    / (average_input_plus_output_length

GLM 5.3 Flash: architecture

Data flow

Vision/text → KDA or pooled sparse MLA → four-stream mHC → shared/routed MoE → repeat → text head; MTP verifies and commits both token and recurrent state.

How the parts work together

Most text layers use KDA, while periodic NoPE sparse-MLA layers retrieve selected history. NoPE means that those attention projections do not use the ordinary rotary-position component; it does not mean that the whole model has no way to process sequence structure. The attention indexer includes pooled compression and a tail-selection mechanism.

Manifold-constrained hyper-connections maintain multiple residual streams and constrain how information mixes between them. The repeated Sinkhorn normalization configured for these connections is a specific model operation, not a generic replacement for the RMSNorm layer. Fusing residual communication must preserve that transformation.

The MoE has many more resident experts than each token activates. Its shared path, dense prefix and router remain part of the total compute and memory budget. A vision stack maps images and video frames into the text network’s representation; limiting image count is an admission-control decision as well as a preprocessing decision.

The native MTP layer is served through different APIs in the two engines. SGLang’s current recipe uses the EAGLE algorithm spelling for this native MTP path. That does not mean the model is using an unrelated external EAGLE checkpoint.

GLM 5.3: architecture

Data flow

Tokens → dense prefix → MLA latent cache + DSA index selection → routed/shared experts → repeat → output; optional MTP → target verification.

How the parts work together

The configuration describes MLA with a separate sparse-attention indexer. The model first constructs representations that make token-history storage cheaper than retaining a separate full key/value vector for every query head. The indexer then selects a limited subset of history for the more expensive attention operation. Compression of what is stored and sparsification of what is read are distinct optimizations.

A dense prefix is followed by routed MoE layers. Shared experts provide a common feed-forward contribution while selected routed experts specialize the token transformation. The router uses its own numerical precision and score function; expert quantization is not permission to quantize router decisions without validation.

The index-selection frequency exposes reuse across layers. Reusing index selections can avoid repeated work, but correctness depends on the implementation’s layer boundaries and index cache. It is not equivalent to asking every layer to select a fresh arbitrary top-k set.

The next-token-prediction extension can propose multiple steps for speculative serving. It does not convert the main model into a dense small model. Generation remains a target-model process with draft verification and cache bookkeeping.

reports/DECISIONS.md

Decision record

ADR 001: Separate model architecture from export producer

The same family can have native, NVIDIA, RedHat and Inferact artifacts with different quantization contracts. Keep each under the originating company and record producer-specific repository IDs. Rejected alternative: one flat “FP4 models” list that hides lineage and loader differences.

ADR 002: Use evidence stages instead of a binary supported flag

A model can be registered yet fail to import, load mixed scales, preserve state or parse tool calls. Record source evidence, compatibility probes, blocked paths and local benchmark status separately. Rejected alternative: a model-card widget means full production support.

ADR 003: Do not select eight-way tensor parallelism by habit

Large MoE targets and small dense targets stress different resources. Compare exact TP/DP/EP layouts and per-GPU replicas under the same node-wide workload. Rejected alternative: every model must use all eight GPUs in one tensor-parallel group.

ADR 004: Keep the control plane separate from the inference runtime

KServe/Kubernetes govern placement, health and rollout; vLLM/SGLang execute numerical inference. First validate a one-node target-only runtime, then add orchestration and only measured-benefit disaggregation. Rejected alternative: use a control-plane product as evidence of a faster kernel.

ADR 005: Metadata and image pins precede production

Resolve mutable model IDs and nightly tags to immutable identities, preserve raw metadata and compare outputs. Keep current source/release observations without claiming tested nightly binaries. Rejected alternative: a moving latest command is reproducible.

These are engineering decisions derived from the framework comparison, source review and memory analysis. They are not empirical performance results.

GLOSSARY.md

Glossary: meaning, purpose and analogy

Use the analogies to build intuition, not as exact mathematics. Architecture-specific terms link back to the company reports; numeric and kernel claims are sourced in the evidence register, precision report and framework reviews. Unverified expansions are explicitly left as project/configuration names.

Token

Tokenizer unit. A piece of text or a model-specific input symbol, not necessarily a word.

Analogy: A page is cut into differently sized tiles; count tiles, not words.

Tokenizer / chat template

Text encoding and conversation serialization. Convert content and roles into the exact IDs/boundaries the model learned. Wrong tool/reasoning boundaries can break an otherwise fluent endpoint.

Analogy: The same message written in the wrong envelope format reaches the wrong desk.

Parameter / weight

Learned numerical value. Total weights drive storage; active weights approximate work per token only under stated accounting.

Analogy: All books on the shelves versus the books consulted for one question.

Dense

All ordinary feed-forward layers participate. No expert router chooses a small subset of the model’s MLPs per token.

Analogy: One permanent team reviews every paragraph.

MLP / FFN

Multilayer perceptron / feed-forward network. The transformations within a decoder block after or alongside attention; can be dense or replaced by experts.

Analogy: An editing workshop transforms what the reader has gathered.

MoE

Mixture of Experts. A router chooses a small number of expert networks per token. All experts still need storage somewhere unless deliberately offloaded.

Analogy: A large hospital employs many specialists; only a few see one patient.

Top-k routing

Select k routed experts. The number of selected experts is not the number resident in memory. Shared experts can add work beyond routed top-k.

Analogy: Two assigned specialists plus the general practitioner still count as three workers.

Shared expert

Always-used expert branch in the relevant architecture. Distinguish always-on shared computation from token-selected routed experts.

Analogy: A common reception desk supports every specialist appointment.

Latent MoE

Experts operating through a reduced representation. Kimi projects into a smaller expert space and back. Layer dimensions and kernels must match that interface.

Analogy: Specialists exchange compact forms rather than the entire case folder.

Attention

Context-dependent information lookup. Query/key comparisons determine how values contribute to a token’s representation.

Analogy: A reader searches previous notes before choosing the next sentence.

MHA / GQA / MQA

Multi-head / grouped-query / multi-query attention. Query heads can share key/value heads, reducing cached K/V. Always read explicit dimensions.

Analogy: Several readers share fewer reference notebooks.

KV cache

Key/value cache. Saved attention data avoids recalculating past token projections. It grows with context in ordinary full attention.

Analogy: Keep the reference notes instead of rereading the entire source every time.

MLA

Multi-head Latent Attention. A model-specific compressed latent representation changes projection and cache layout. Ordinary GQA memory arithmetic is not a full MLA estimate.

Analogy: Compress the reference folder before storing it, then reconstruct what is needed.

DSA

DeepSeek Sparse Attention. An indexed selection mechanism reduces which past representations receive expensive attention. Index and selected-value caches are distinct.

Analogy: A catalog points to relevant shelves rather than scanning every book.

QSA

Qwen sparse-attention path. Qwen’s particular sparse/indexed attention implementation must be read with its own compression and index shapes.

Analogy: A different library uses a different catalog; shelf numbers are not interchangeable.

SWA

Sliding-window attention. Restricts a layer’s direct attention to a recent window; some architectures interleave global layers.

Analogy: Keep recent pages on the desk, occasionally consult the complete archive.

NoPE

No positional encoding in the named path. A specific attention path omits ordinary positional encoding; not a claim the whole model has no ordering information.

Analogy: One index sorts by content, while other mechanisms preserve sequence.

RoPE

Rotary position embedding. Transforms components according to position. Partial rotary dimensions can differ from total head size.

Analogy: Position stamps help distinguish otherwise similar entries.

YaRN

A RoPE context-extension method. Its configured scale/original window affects position handling; a larger limit alone does not guarantee useful long-context accuracy.

Analogy: Stretch the map’s coordinate scale, then check that landmarks still line up.

KDA

Kimi Delta Attention. A gated recurrent/linear-attention mechanism with its own state and convolution path. It cannot be treated as ordinary token KV alone.

Analogy: Maintain and revise a compact notebook as each sentence arrives.

GDN

Gated DeltaNet. A gated delta-rule recurrent attention family used in Qwen hybrids; its state dimension and cache slots affect concurrency.

Analogy: The notebook has rules for what to replace, retain or forget.

SSM / recurrent state

State-space model / persistent running representation. Serving terminology may group recurrent caches under SSM/Mamba labels even for different linear-attention architectures.

Analogy: A running summary survives between steps; copying it also consumes space.

Convolution state

Short recent-input history. Hybrid blocks may require convolution buffers as well as matrix state. Disaggregation and rollback must preserve both.

Analogy: The running summary also carries a small stack of the latest pages.

mHC

Manifold-constrained Hyper-Connections. Multiple residual streams with constrained mixing; GLM Flash and DeepSeek expose related configuration. Do not infer Qwen gated residuals are identical.

Analogy: Several parallel discussion threads exchange information under stability rules.

Sinkhorn iterations

Iterative matrix normalization. An implementation mechanism for constrained mixing; iteration count is a real architecture/accuracy parameter, not a free speed knob.

Analogy: Repeatedly balance row and column totals until the routing ledger is consistent.

Residual connection

Bypass added or mixed with a transformation. Allows information to flow around a block; newer architectures can mix several residual streams.

Analogy: Keep the original draft available while applying an edit.

RMSNorm

Root-mean-square normalization. Rescales activations using RMS statistics. Fusion can reduce kernel/communication overhead without intentionally changing the mathematical contract.

Analogy: Adjust loudness without rewriting the speech.

GELU / SwiGLU / SiTU

Activation/operator names. GELU and gated Swish-family operations differ; Kimi’s SiTU coefficients and scale placement are part of its checkpoint contract. This atlas does not invent an unverified long-form expansion for SiTU.

Analogy: Different workshop machines need different settings, even when their input sizes match.

PLE / n-gram tables

Checkpoint labels for lexical/table components. Flash Next contains a large separately reported n-gram component. The long-form PLE expansion was not independently established here; retain the literal config label.

Analogy: A large phrase dictionary still occupies shelves even when only one entry is looked up.

MTP / NextN

Multi-token prediction / implementation naming. Auxiliary prediction structures can support speculative serving. A legacy config key does not prove the current engine should use its MTP algorithm.

Analogy: An attached assistant proposes a continuation, but the main writer approves it.

DSpark

Speculative-decoding project/method name. Match target features, checkpoint, proposal semantics and verification implementation. No invented acronym expansion.

Analogy: A fast assistant sketches a phrase before the lead editor checks it.

EAGLE

Speculative-decoding family / engine algorithm option. An engine’s EAGLE switch can route a model’s built-in MTP implementation; it does not necessarily mean an unrelated external draft model.

Analogy: The software menu names a workflow, not always the exact assistant employed.

Speculative acceptance

Verified draft tokens retained. Use observed acceptance under the actual workload and sampling; simulated acceptance is a synthetic experiment.

Analogy: Count edits the lead editor really accepted, not edits assumed accepted.

BF16 / FP16

Brain floating point 16 / 16-bit floating point. Two-byte formats with different exponent/significand allocations. Neither spelling establishes every tensor’s effective storage dtype.

Analogy: Two measuring tapes with the same number of markings but different range/detail trade-offs.

FP8 / E4M3 / E5M2

8-bit floating point / exponent-mantissa allocations. Smaller numeric formats rely on scaling and calibrated/dynamic ranges. FP8 in a filename is not a complete tensor-level specification.

Analogy: Write shorter numbers but retain the scale printed beside them.

NVFP4

NVIDIA four-bit floating-point representation. Combines FP4 values with block/global scaling. Scale precision, block size, packing and kernels matter.

Analogy: A compact ruler with a small local scale legend for each group.

MXFP4 / MXFP8

Microscaled four-/eight-bit floating point. Microscaling is a different contract from NVFP4. Kimi native MXFP4/MXFP8 is not the same export as NVIDIA NVFP4.

Analogy: Two compression formats can use four-bit symbols yet different dictionaries.

W4A4 / W4A8 / W4A16

Weight bits / activation bits. Weight and activation precision are independent. These labels do not describe KV-cache or recurrent-state precision.

Analogy: The archived recipe, active worksheet and notebook can each use a different paper size.

FP8_PB_WO

ModelOpt per-block FP8 weight-only label. A loader must handle exported block scales, shapes and mixed-module dispatch. Runtime activation processing may still be implementation-specific.

Analogy: The storage label is not a complete instruction manual for the calculation.

PTQ / QAT

Post-training quantization / quantization-aware training. PTQ transforms a trained checkpoint; QAT exposes training to quantization effects. Either still needs task-quality verification.

Analogy: Shrink a completed drawing versus practice drawing on the smaller grid.

Calibration

Estimate numeric ranges using representative samples. Calibration data/algorithm can affect quality. Do not compare exports as if all four-bit artifacts were equivalent.

Analogy: Set a camera’s exposure using scenes similar to those it will actually photograph.

ModelOpt / compressed-tensors

NVIDIA optimization tooling / serialized quantization framework. Exporter metadata directs loading and kernels. These are tool/format names, not universal interchangeable quantization flags.

Analogy: Two manufacturers package similar components with different wiring diagrams.

GPU / HBM

Graphics processing unit / high-bandwidth memory. The compute accelerator and its local high-bandwidth storage. Advertised capacity is not fully available for weights.

Analogy: A workshop plus its fast on-site warehouse.

SM / compute capability

Streaming multiprocessor / GPU architecture feature level. Kernels are compiled for compatible GPU targets. B300 is not equivalent to every device marketed as Blackwell.

Analogy: Related engines can still require different compatible parts.

SXM / SXM6-AC

Module/interface designation / user-provided OEM label. The precise AC-labeled server variant was not independently identified. Check the actual supplier inventory and board topology.

Analogy: A component label is not a complete vehicle specification.

NVLink / NVSwitch

NVIDIA GPU interconnect / switching fabric. Fast GPU communication can make sharding practical; it does not make eight GPUs one uniformly shared memory allocation.

Analogy: Fast roads join warehouses, but stock still lives at particular locations.

PCIe / NUMA

Peripheral Component Interconnect Express / non-uniform memory access. Host-device paths and CPU-memory locality affect input, communication and startup.

Analogy: Distance to the loading dock matters even with a fast workshop.

TP

Tensor parallelism. Split tensor work across ranks; introduces communication. Smaller dense models can benefit more from replicas.

Analogy: Several people work on sections of the same sentence and must synchronize.

DP

Data parallelism. Independent request/data work; attention-DP and full-model replicas are not necessarily the same MoE topology.

Analogy: Several reception desks handle separate customers.

EP

Expert parallelism. Distribute experts across existing ranks and route tokens between them. Active expert count does not multiply available memory.

Analogy: Specialists occupy different buildings and cases travel between them.

PP

Pipeline parallelism. Place sequential layer stages on different ranks. Scheduling bubbles and batch behavior affect utilization.

Analogy: An assembly line waits when the previous station has not delivered its part.

CP / DCP

Context parallelism / decode context parallelism. Split context-related attention work/cache under engine-specific semantics. Do not blindly divide all caches and state by this factor.

Analogy: Several archivists divide the reference pages, not necessarily every notebook.

Prefill / decode

Process prompt / generate subsequent tokens. Different workload phases with different compute/bandwidth profiles. Separating them adds transfer and scheduling costs.

Analogy: Read the brief first, then dictate the response a word at a time.

PD disaggregation

Prefill/decode separation. Dedicated pools can reduce interference, but hybrid state and KV transfer must match exactly.

Analogy: Transfer the case from a reading team to a writing team without losing notes.

Continuous batching

Dynamic request scheduling. Completed requests leave and new ones enter execution without waiting for a fixed batch to finish.

Analogy: A restaurant fills available seats as diners leave.

Paged attention / prefix cache

Managed KV blocks / reuse of shared prompt work. Paging improves allocation behavior; prefix caching reuses matching work. Neither proves hybrid-state or cross-tenant isolation is correct.

Analogy: Manage notebooks in reusable page blocks and keep copies of common introductions.

Radix cache

Prefix tree organized cache. Shared token prefixes can be represented by common tree paths. Eviction, state snapshots and tenant isolation still matter.

Analogy: Many routes share the same first streets before branching.

CUDA Graph

Recorded GPU execution graph. Replays work with less launch overhead under shape/state constraints; graph capture reserves memory and needs correctness testing.

Analogy: Record a repeatable production sequence instead of issuing every instruction again.

GEMM

General matrix multiplication. Core tensor operation. Fused or low-precision kernels are useful only for supported shapes, scales and hardware.

Analogy: A specialized press processes many entries together.

FlashInfer / FlashMLA / DeepGEMM

Kernel-library project names. Different libraries implement attention, latent-attention or matrix/MoE paths. Presence in an image does not prove the intended kernel was selected.

Analogy: A toolkit may contain the correct wrench, but the mechanic still has to use it.

TRT-LLM / CUTLASS

TensorRT-LLM / CUDA templates for linear-algebra subroutines. Kernel/backend families may be called by vLLM or SGLang; using a TRT-LLM MoE kernel does not replace the entire serving engine.

Analogy: A workshop can use another maker’s machine without changing ownership.

NCCL / DeepEP / all-reduce / all-to-all

NVIDIA collective communications / expert communication library / collective patterns. All-reduce combines values; all-to-all redistributes different payloads among ranks. Communication topology must match parallelism.

Analogy: A group totals everyone’s results, or sends different cases to the right specialists.

NIXL / RDMA

NVIDIA inference-transfer library (NIXL) / remote direct memory access. Transfer infrastructure used in some disaggregated designs. Exact buffer/state layouts remain an engine contract.

Analogy: A courier can move a folder quickly but cannot fix missing pages.

vLLM / SGLang

Serving-runtime project names. Both coordinate model execution, scheduling and kernels. Their argument names and support details differ.

Analogy: Two workshop operating systems, each with different compatible machinery.

KServe / Kubernetes

Serving control plane / cluster orchestration. KServe manages serving resources on Kubernetes; it is not a replacement numerical inference engine.

Analogy: The building manager assigns rooms and health checks; the workshop still performs the work.

CRD / CR / controller

Custom Resource Definition / Custom Resource / reconciliation program. The CRD defines an API shape; a CR is an instance; the controller acts on it. Schema acceptance alone does not prove model readiness.

Analogy: A form template, a completed order, and the staff who actually fulfill it.

InferenceService / LLMInferenceService

KServe resource kinds. The ordinary serving resource and LLM-specialized coordination surface have different version/integration requirements.

Analogy: A standard booking versus a coordinated multi-room production order.

LWS / EPP / Gateway API

LeaderWorkerSet / endpoint picker / Kubernetes gateway API. Building blocks for coordinated workers and routing; exact installation and engine adapters must be validated.

Analogy: Keep a team together and send each customer to the correct entrance.

PVC / image digest

PersistentVolumeClaim / immutable container content identifier. The PVC supplies storage; a digest pins image content. A syntactically valid digest does not prove availability or model compatibility.

Analogy: A warehouse reservation and a sealed versioned toolbox.

TTFT / TPOT / ITL

Time to first token / time per output token / inter-token latency. Different latency measurements. Semantic SSE chunks are not guaranteed to be individual tokens.

Analogy: Wait for the speaker to begin, then measure pace; sentence delivery is not syllable timing.

Throughput / goodput / SLO

Work per time / acceptable work per time / service-level objective. More tokens per second can hide poor tail latency or failures. Goodput counts work meeting declared requirements.

Analogy: Meals produced versus meals delivered correctly and on time.

p50 / p95 / p99

Latency percentiles. Describe distribution tails, not different forms of average. State how failed requests are handled.

Analogy: Most customers wait briefly, but the longest queues still matter.

SSE / API / HTTP

Server-sent events / application programming interface / Hypertext Transfer Protocol. Transport and request interfaces. Correct transport does not guarantee correct tokenization or tool semantics.

Analogy: The telephone line works, but the participants must still speak the same protocol.

GB / GiB

Decimal gigabyte / binary gibibyte. One GB is 1e9 bytes; one GiB is 2^30 bytes. Never subtract capacities expressed in different units without converting.

Analogy: Kilometers and miles can describe the same road but not with the same number.

SHA / pin / nightly

Content identifier / immutable selection / frequently rebuilt development artifact. Pin checkpoint and image independently. Main source, a release tag and a nightly image are different objects.

Analogy: A dated blueprint does not identify the exact assembled machine.

LIMITATIONS.md

Verification boundaries and unresolved work

This is a populated research and engineering atlas, not a certificate that every checkpoint will run on every B300 image. It was assembled on October 15, 2026 from publisher configurations/cards, engine recipes, selected source files and pull-request/release metadata.

Completed

Eight model-family directories contain architecture dimensions, original technical explanations, precision variants, serving reasoning, validation plans and source links. vLLM and SGLang main references and latest releases were retrieved, selected implementation files were inspected, and concrete relevant PR statuses were checked. Local repository code and document-integrity tests are reported in VALIDATION.md.

Not completed or not available

No model weights were downloaded, no inference engine was installed or run, no B300 node was available, and no GPU correctness, throughput, latency, memory or power measurement was performed. No deployed KServe cluster was changed or validated. No nightly container was pulled or tested; the current main-source review is not nightly-binary certification.

Full vLLM and SGLang clones could not be materialized because the local environment could not resolve github.com. The separate connected terminal was unavailable. Selected files were read through the GitHub connector instead. evidence/clone-attempt.log records the local failure; scripts/clone_upstreams.py enables pinned retrieval on a networked host. The ZIP contains authored source-review notes, not complete upstream repositories.

The exact OEM string “B300 SXM6-AC” was supplied by the user and was not independently identified. The hardware discussion uses NVIDIA’s B300 documentation conditionally; CPU, networking, physical topology, cooling, firmware, power limits and usable memory need actual node inventory. A DGX B300 reference specification does not identify the user's server.

Selected configuration fields are curated projections, not byte-for-byte complete original configs. Original raw model cards/configs and full source trees are not archived in this ZIP. Most model citations use mutable main URLs; one Qwen Flash Next base revision was resolved. All other model revisions intentionally remain null until fetched. Local artifact checksums prove local integrity, not historical authenticity of remote pages.

Several precision requests have no independently audited exact release: in particular a fully FP8 Kimi K3 is not established. Some derivative repositories are supported by an engine recipe rather than a separately inspected complete export. These distinctions remain visible in the catalog and profiles; missing facts are not filled with neighboring model values.

DeepSeek's 284B/13B figures are family-level metadata, not an exact July-31 tensor census. GLM’s differently scoped parameter headlines are not reconciled into false precision. Advertised long-context limits do not establish accuracy or practical concurrency at that length. Licenses in the catalog are identification notes, not redistribution or commercial-use clearance; inspect all base and derivative terms.

Meaning of “best” in this repository

Recommendations are starting hypotheses justified by memory architecture, available implementation paths and source evidence. A winner requires the same workload, input/output distribution, quality threshold, latency target, hardware, effective precision and natural speculative acceptance. Published author benchmarks are not reproduced results. In particular, simulated-acceptance Kimi DSpark results cannot certify application speedup.
