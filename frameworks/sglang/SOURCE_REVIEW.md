## Memory and scheduling settings

At v0.5.21, `--mem-fraction-static` budgets static allocations including weights and cache pools. The allocator starts from free memory after loading weights, subtracts runtime slack based on the pre-load memory observation, reserves multimodal memory and accounts for hybrid state. It is not directly equivalent to vLLM's utilization formula. Target and draft weights already resident reduce the available budget. `--mamba-full-memory-ratio` allocates state relative to full-attention KV, while `--max-mamba-cache-size` can directly constrain the state pool; either can change effective concurrency. [RR-ENG-G-STABLE-SCHEDULE](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/arg_groups/fields/schedule.py), [RR-ENG-G-STABLE-KV_CACHE_CONFIGURATOR](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/mem_cache/kv_cache_configurator.py).

Use SGLang's own cache spellings: the released choices include `auto`, `bf16`/`bfloat16`, `fp8_e4m3` and `fp8_e5m2`; bare vLLM `fp8` is not listed. These choices do not change every recurrent-state dtype or make every attention backend compatible. Radix reuse and CPU/GPU overlap default on at the field level, through `disable_radix_cache=False` and `disable_overlap_schedule=False`; model resolution can constrain them. `--chunked-prefill-size` is a token count, with `-1` disabling chunking, and its unset value is resolved later. Log effective pool sizes, backends and scheduling settings before comparing memory fractions or chunk sizes across engines. [RR-ENG-G-STABLE-MODEL](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/arg_groups/fields/model.py), [RR-ENG-G-STABLE-MEMORY](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/arg_groups/fields/memory.py), [RR-ENG-G-STABLE-SCHEDULE](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/arg_groups/fields/schedule.py).

## October 16 DSpark fix: exact scope

Commit `fad7d95a7f1a942e039f74eb2d319da29311b8cb` / #44673 merged at **08:18:59 UTC**. For **DeepSeek V4.1 + DSpark + encoder SWA bounded replay on CUDA**, draft sliding-window attention moves from paged, tree-owned storage to a per-request ring. Its ring width is sliding window plus maximum draft tokens. Prefix hits reset the valid range so a reused slot cannot expose the previous request's rows. Removing the draft's SWA component prevents its eviction from unnecessarily shortening reusable target prefixes. HIP retains the paged draft path. This is not a demonstrated V4 Flash **0731** optimization. [RR-ENG-GDS-PR](https://api.github.com/repos/sgl-project/sglang/pulls/44673), [RR-ENG-GDS-DIFF](https://github.com/sgl-project/sglang/commit/fad7d95a7f1a942e039f74eb2d319da29311b8cb.diff).

The report's `3d61bdd…` head includes the commit; stable v0.5.21 lacks the new draft-ring implementation. The latest advertised wheel source `f9df33494a` is **25 commits behind this fix**, so an October 16 wheel name does not prove inclusion. The author reports a four-GB300 V4.1 test; no B300 result was reproduced here. A relevant follow-up would stress eviction, prefix reuse, slot reuse, rejection and graph replay while recording actual acceptance and quality. [RR-ENG-GDS-COMPARE-REPORT](https://api.github.com/repos/sgl-project/sglang/compare/fad7d95a7f1a942e039f74eb2d319da29311b8cb...3d61bdd2c9db507e0b299488d1218b596364f42c), [RR-ENG-G-STABLE-DSPOOL](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/mem_cache/deepseek_v4_memory_pool.py), [RR-ENG-GDS-COMPARE-WHEEL](https://api.github.com/repos/sgl-project/sglang/compare/fad7d95a7f1a942e039f74eb2d319da29311b8cb...f9df33494a).

## Hybrid state and prefix reuse

A hybrid request needs attention KV and recurrent/convolution state representing the same prefix. Branches, overlapping execution and speculative verification can require several state slots per request. Giving nearly all post-weight HBM to KV can leave free token pages but too few state slots to admit work. The useful split depends on request length, cache strategy and speculation. Record the **resolved** strategy and pool capacities; a generic default and a model-specific recipe need not resolve identically. [GEXP-QWEN](https://docs.sglang.io/cookbook/autoregressive/Qwen/Qwen3.8-27B), [GEXP-GLMFLASH](https://docs.sglang.io/cookbook/autoregressive/GLM/GLM-5.3-Flash).

ReplaySSM uses a replay ring instead of ordinary per-request speculative intermediate-state slots. PR #40517 made its KDA gate capability-based, allowing GLM-5.3 Flash rather than depending on a Kimi-specific config class; v0.5.21 lists the change. This motivates memory and rollback comparisons, without establishing a latency win. [GEXP-PR40517](https://github.com/sgl-project/sglang/pull/40517), [GEXP-REL](https://github.com/sgl-project/sglang/releases/tag/v0.5.21).

The int8 checkpoint pool is **already present in stable source**. It compresses idle radix-owned temporal state, retains convolution windows at their native dtype and restores checkpoints into active slots. This differs from reducing active-state arithmetic precision. Scales, convolution state and the additional pool still consume memory. Source comments describing quality do not replace long-conversation evaluation: rounding at a cache hit changes the starting state for later computation. [GEXP-STABLE-MAMBA](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/mem_cache/mamba_checkpoint_pool.py), [GEXP-SRC-MAMBA](https://raw.githubusercontent.com/sgl-project/sglang/4e0609ea277d09393d752fcb79181e3416d94c56/python/sglang/srt/mem_cache/mamba_checkpoint_pool.py).

The unified radix cache groups full-attention, sliding-window and recurrent components behind a tree core. Rust is a v0.5.21 feature, but current source can resolve even an explicit Rust request to Python for unsupported components, session-aware caching, platform or installation constraints. Check the logged concrete core before comparing treatments. [GEXP-PR39627](https://github.com/sgl-project/sglang/pull/39627), [GEXP-SRC-TREECORE](https://raw.githubusercontent.com/sgl-project/sglang/4e0609ea277d09393d752fcb79181e3416d94c56/python/sglang/srt/mem_cache/unified_cache/tree_core_registry.py), [GEXP-SRC-CACHE](https://raw.githubusercontent.com/sgl-project/sglang/4e0609ea277d09393d752fcb79181e3416d94c56/python/sglang/srt/mem_cache/unified_radix_cache.py).

HiCache extends reuse to host memory and optionally storage. L2 belongs to one engine instance; independent replicas do not automatically share it. L3 supports cross-instance reuse only through an appropriately configured backend and namespace. Hits can save prefill work but add transfer time, CPU memory demand and storage traffic. Compare cold, GPU-hit, host-hit and storage-hit cases separately, then replay the real mixture. [GEXP-HICACHE](https://docs.sglang.io/docs/advanced_features/hicache_design).

Main PR #44173 adds an opt-in `buffer_only` optimization: an SWA component backs up the trailing window required at a node endpoint. Source trims transfer rows, storage keys and dependent sidecars consistently. This can reduce SWA writes, not every component's memory. Validate node splits, hits inside nodes, unequal windows and storage misses before adoption. [GEXP-PR44173](https://github.com/sgl-project/sglang/pull/44173), [GEXP-SRC-SWA](https://raw.githubusercontent.com/sgl-project/sglang/4e0609ea277d09393d752fcb79181e3416d94c56/python/sglang/srt/mem_cache/buffer_mode/pipeline.py).

## Precision must reach the intended implementation

The model registry logs and skips non-strict import failures, and can normalize an unresolved architecture to a Transformers fallback. Capture the resolved class and warnings; accepting a model name does not establish its optimized path. [GEXP-SRC-REG](https://raw.githubusercontent.com/sgl-project/sglang/4e0609ea277d09393d752fcb79181e3416d94c56/python/sglang/srt/models/registry.py).

ModelOpt dispatches modules through a quantization map. Current source recognizes both `FP8_PB_WO` and `FP8_BLOCK_SCALES` for linears and fused experts, derives their block size and rejects conflicting sizes. Released PR #38726 addresses the exact NVIDIA Qwen Flash Next case in which metadata copies name MTP experts differently. An NVFP4-labeled checkpoint can still require FP8 expert, attention and embedding handling. Record loaded module methods and exclusions for the exact export. [GEXP-PR38726](https://github.com/sgl-project/sglang/pull/38726), [GEXP-SRC-QUANT](https://raw.githubusercontent.com/sgl-project/sglang/4e0609ea277d09393d752fcb79181e3416d94c56/python/sglang/srt/layers/quantization/modelopt_quant.py).

The earlier Kimi PR #35077 is included in v0.5.21 source. Its author reported correctness on eight **GB300** GPUs and no speed test. That supports a B300 compatibility candidate, not measured B300 throughput. [KIMIPR](https://github.com/sgl-project/sglang/pull/35077), [GREL-KIMI-ANCESTRY](https://github.com/sgl-project/sglang/compare/5f128395910dafb98c34083dc26cb790c7674d34...v0.5.21).

## Attention and quantization controls are separate contracts

The v0.5.21 registry has distinct `fa4`, `flashinfer`, `dsa`, `qsa` and `dsv4` factories. Its `nsa` spelling is a deprecated alias for DSA; it does not establish support for every algorithm published under “Native Sparse Attention.” The CUDA DeepSeek V4 route selects its specialized backend. Hybrid models additionally wrap full/sparse attention with GDN or KDA state handling. Selecting `fa4` therefore does not replace every attention-like layer in these models. [ATTR-S-ATTENTION-REGISTRY](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/layers/attention/attention_registry.py).

SGLang can resolve different prefill and decode backends, and its linear-attention controls have separate decode/prefill/verification constraints. Kernel-library names also overlap: FlashInfer supplies recurrent kernels as well as softmax attention and GEMMs. A FlashInfer GDN log entry is not evidence that a layer uses FlashAttention. Compare the effective layer and phase, then its cache/state layout, before transferring a vLLM backend recommendation. [ATTR-S-ATTENTION-HOOK](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/arg_groups/attention_hook.py).

The released cache-dtype field includes `mxfp8`, `nvfp4` and `fp4_mx_block16` alongside the FP8/BF16 choices. These are distinct cache recipes; accepting the argument is not proof of support for an arbitrary model, speculative path or attention backend. They also do not select weight/activation quantization. Use the release-matched implementation when the moving documentation matrix differs. [ATTR-S-MODEL-FIELDS](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/arg_groups/fields/model.py), [current backend documentation](https://docs.sglang.io/docs/advanced_features/attention_backend).

## FP8 KV and FA4: phase-specific source findings

**Rechecked October 16 against stable v0.5.21 (`e00930c…`) and later main `baf451fcd6f54962c7db7dc30c636cb534ba1f2a` (09:47:41 UTC commit).** The findings below describe inspected source, not an executed configuration. Main is a separate source observation from the earlier table and the published nightly wheel.

### Storage format does not determine both attention matmuls

`--kv-cache-dtype fp8_e4m3` selects ordinary FP8 cache storage; `mxfp8` is a separate block-scaled recipe. `--dtype`, checkpoint quantization metadata and KV scaling factors remain separate inputs. An FP8 or NVFP4 weight export alone does not set the KV dtype, quantize attention Q or establish FA4 compatibility. The field help says `auto` uses model dtype and warns that absent FP8 KV scaling factors can fall back to 1.0; preserve the exact export's scale metadata rather than assuming unit scales are calibrated. [FP8S-S-MODEL](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/arg_groups/fields/model.py).

| Inspected route | Actual data/arithmetic contract | Boundary |
| --- | --- | --- |
| Ordinary FP8, FA4 **decode**, eligible MHA/GQA | The backend casts Q to cache dtype for head dimensions ≤256 and supplies available layer K/V descales. The vendored generic SM100 kernel uses input Q/K dtype for QK and V dtype for PV, with **FP32 accumulation**; ordinary all-FP8 inputs therefore use FP8 operands for both matmuls and BF16 output | Kernel capability does not qualify every head dimension, model, prefill or speculative route |
| Ordinary FP8, FA4 **prefill**, ordinary BF16-Q MHA/GQA | Both inspected versions explicitly skip that Q cast/descale branch for FA4 prefill. The plain pool exposes FP8 K/V, while the vendored interface requires matching Q/K/V dtypes | The documentation marks FA4 MHA FP8 KV unsupported. The inspected generic path does **not** substantiate a complete `fa4` prefill + `fp8_e4m3` recipe; selecting FlashInfer decode does not repair its prefill dtype mismatch |
| **MXFP8**, FA4 | Q/K use FP8 E4M3 with per-32-element UE8M0 scales and block-scaled QK. V is stored FP8, dequantized **inside the kernel to BF16**, and PV uses BF16 operands; accumulators remain FP32 | Requires the matching Q/scale producer and cache layout. It is neither ordinary E4M3 KV nor “FP8 for every attention matmul” |

[FP8S-S-FA](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/layers/attention/flashattention_backend.py), [FP8S-M-FA](https://raw.githubusercontent.com/sgl-project/sglang/baf451fcd6f54962c7db7dc30c636cb534ba1f2a/python/sglang/srt/layers/attention/flashattention_backend.py), [FP8S-S-POOL](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/mem_cache/memory_pool.py), [FP8S-M-FAINTERFACE](https://raw.githubusercontent.com/sgl-project/sglang/baf451fcd6f54962c7db7dc30c636cb534ba1f2a/python/sglang/kernels/ops/attention/flash_attn/cute/interface.py), [FP8S-M-FAKERNEL](https://raw.githubusercontent.com/sgl-project/sglang/baf451fcd6f54962c7db7dc30c636cb534ba1f2a/python/sglang/kernels/ops/attention/flash_attn/cute/flash_fwd_sm100.py), [FP8S-M-ATTDOC](https://raw.githubusercontent.com/sgl-project/sglang/baf451fcd6f54962c7db7dc30c636cb534ba1f2a/docs/docs/advanced_features/attention_backend.mdx).

### Backend pairs and page sizes

The following are conditional argument fragments, not launch commands or model recommendations. They assume the identified attention family and a compatible shared cache; sparse and recurrent layers retain their own contracts.

| Pair or setting | Supported interpretation and limits |
| --- | --- |
| Ordinary MHA/GQA, BF16 cache: `--prefill-attention-backend fa4 --decode-attention-backend flashinfer --kv-cache-dtype bf16` | The hybrid wrapper supports separate phase backends. Ordinary non-MLA FA4 on SM100/SM103 forces **page size 128**; `--page-size 64` is not a retained tuning choice. This fragment does not establish compatibility with an arbitrary model, graph mode or speculation |
| FA4 prefill + `trtllm_mha` decode | No blanket ban for BF16/ordinary FP8 storage is established by the KV4 check. On SM100, the forced page128 reaches TRT-LLM's dynamic-page kernels, which require **GQA (Q heads/KV heads >1), equal QK/V head dimensions**, a power-of-two page size and the relevant FlashInfer kernel version (the override notes ≥0.6.12). Ordinary FP8 FA4 prefill still has the dtype boundary above |
| Ordinary MLA, FA4 prefill + `trtllm_mla` decode | Upstream illustrates this with **DeepSeek-R1**, not V3.2. TRT-LLM MLA requires an MLA model, Blackwell, compatible latent-KV layout, and page32 or64 (otherwise resolved to64); its dtype gate allows `auto`, `bf16`, `fp8_e4m3`. The FA4 absorbed path requires its supported latent dimensions and lacks split-KV; the registry rejects TRT-LLM MLA decode with **DCP plus speculation**. A dtype gate alone does not validate the whole pair |
| FA4 with **KV4** | The warning about `trtllm_mha` incompatibility is in a KV4-specific section. The source's FA4 MHA KV4 branch permits only Triton/Torch Native/Flex decode. Native `nvfp4` has another contract: TRT-LLM MHA decode, with native TRT-LLM or FP8-workspace FlashInfer prefill. Do not transfer these restrictions or scale layouts to ordinary FP8 |

[FP8S-M-OVERRIDES](https://raw.githubusercontent.com/sgl-project/sglang/baf451fcd6f54962c7db7dc30c636cb534ba1f2a/python/sglang/srt/arg_groups/overrides.py), [FP8S-S-MHA](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/layers/attention/trtllm_mha_backend.py), [FP8S-M-HYBRID](https://raw.githubusercontent.com/sgl-project/sglang/baf451fcd6f54962c7db7dc30c636cb534ba1f2a/python/sglang/srt/layers/attention/hybrid_attn_backend.py), [FP8S-M-REGISTRY](https://raw.githubusercontent.com/sgl-project/sglang/baf451fcd6f54962c7db7dc30c636cb534ba1f2a/python/sglang/srt/layers/attention/attention_registry.py), [FP8S-M-KVHOOK](https://raw.githubusercontent.com/sgl-project/sglang/baf451fcd6f54962c7db7dc30c636cb534ba1f2a/python/sglang/srt/arg_groups/kv_cache_hook.py), [FP8S-S-FP4CONTRACT](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/layers/quantization/fp4_kv_cache_quant_method.py).

The page128 force skips the EAGLE `topk>1` cascade case, whose source comment requires page1; that exception does not authorize page64. Main also has a separate diffusion-model exception. Radix matching and insertion round down to whole pages: a 65-token shared prefix can contribute one 64-token page at page64, but none at page128. Its tail still needs processing and can remain in the active request; it is not discarded from the prompt. Larger pages can therefore reduce reusable prefix length, independently of kernel speed. [FP8S-S-RADIX](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/mem_cache/radix_cache.py), [FP8S-S-UNIFIED](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/mem_cache/unified_radix_cache.py), [FP8S-M-OVERRIDES](https://raw.githubusercontent.com/sgl-project/sglang/baf451fcd6f54962c7db7dc30c636cb534ba1f2a/python/sglang/srt/arg_groups/overrides.py).

**DeepSeek V3.2 is a DSA case, not the ordinary MLA example.** Its default model hook selects `dsa`; the recipe uses `--dsa-prefill-backend` / `--dsa-decode-backend` and a learned indexer. It lists Blackwell FP8 defaults as `trtllm` for both DSA phases. An explicit generic FA4 override bypasses the unset-backend default; that is not evidence for a correct V3.2 FA4 recipe. Its adaptive short-prefill dense path is internal to DSA and does not establish a universal dense-attention replacement. Do not transfer this recipe to the atlas's DeepSeek V4 Flash 0731. [FP8S-M-DSAOVERRIDE](https://raw.githubusercontent.com/sgl-project/sglang/baf451fcd6f54962c7db7dc30c636cb534ba1f2a/python/sglang/srt/arg_groups/model_overrides/deepseek_v2.py), [FP8S-M-DSARECIPE](https://raw.githubusercontent.com/sgl-project/sglang/baf451fcd6f54962c7db7dc30c636cb534ba1f2a/docs/cookbook/autoregressive/DeepSeek/DeepSeek-V3_2.mdx).

### Speculation, memory and performance claims

`--speculative-attention-mode` defaults to **`prefill`** in stable and main. The documentation recommends `decode`; this is not the default or an unconditional improvement. The hybrid wrapper routes target verification by this setting, while draft-backend selection has its own field and algorithm constraints. TRT-LLM MHA permits EAGLE topk1; paged tree speculation has backend-specific gates. The native-NVFP4/FlashInfer-prefill path explicitly forces verification to decode because its transient prefill workspace cannot be refreshed inside the verification graph. That special override is not a rule for every FP8 configuration. [FP8S-S-SPEC](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/arg_groups/fields/spec.py), [FP8S-M-SPEC](https://raw.githubusercontent.com/sgl-project/sglang/baf451fcd6f54962c7db7dc30c636cb534ba1f2a/python/sglang/srt/arg_groups/fields/spec.py), [FP8S-M-SPECHOOK](https://raw.githubusercontent.com/sgl-project/sglang/baf451fcd6f54962c7db7dc30c636cb534ba1f2a/python/sglang/srt/arg_groups/speculative_hook.py), [FP8S-M-HYBRID](https://raw.githubusercontent.com/sgl-project/sglang/baf451fcd6f54962c7db7dc30c636cb534ba1f2a/python/sglang/srt/layers/attention/hybrid_attn_backend.py), [FP8S-M-KVHOOK](https://raw.githubusercontent.com/sgl-project/sglang/baf451fcd6f54962c7db7dc30c636cb534ba1f2a/python/sglang/srt/arg_groups/kv_cache_hook.py).

**`--mem-fraction-static 0.88`–`0.90` is a capacity hypothesis, not a fixed FA4 tile reservation.** SMEM/TMEM tile storage is on-chip, separate from HBM. Actual device-memory consumers include weights, KV and scales, recurrent/draft state, outputs, optional FP32 log-sum-exp and split-KV partial-output buffers, backend workspaces and graph/metadata buffers. The ordinary allocator subtracts runtime slack based on pre-load memory from currently free memory, then reserves multimodal/state memory; neither its formula nor the FA4 interface prescribes a universal 10–12% FA4 HBM tax. A mixed backend can add its own workspace. [FP8S-S-KVCFG](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/mem_cache/kv_cache_configurator.py), [FP8S-M-FAINTERFACE](https://raw.githubusercontent.com/sgl-project/sglang/baf451fcd6f54962c7db7dc30c636cb534ba1f2a/python/sglang/kernels/ops/attention/flash_attn/cute/interface.py), [FP8S-S-FI](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/layers/attention/flashinfer_backend.py), [on-chip attention storage](../../reports/attention-and-fa4.md).

No matched primary result in this review establishes **30–40% TTFT reduction, 60% overlap, a 5–10% unique gain, or a batch1-versus-≥16 crossover** for these eight-B300 configurations. Prefix reuse saves eligible prefill work; FA4 changes the remaining attention work, and neither determines queueing, non-attention execution or decode latency by itself. These figures remain unverified workload hypotheses, not reasons to approve the proposed production commands.
