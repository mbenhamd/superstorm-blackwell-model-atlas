## The important distinctions

Kimi is the capacity-heavy latent-MoE hybrid. GLM 5.3 uses sparse MLA without inheriting Flash’s recurrent architecture. GLM Flash combines KDA, sparse MLA, mHC and vision. DeepSeek 0731 has compressed/sparse attention and a bundled DSpark path. Qwen 27B is dense but hybrid. Flash Next adds a major n-gram table and differently quantized auxiliary path. Gemma is dense with heterogeneous local/global attention. Mistral Medium is dense GQA with a full-history cache. Kimi K3.1 Pro keeps K3's weights topology but changes the attention kernel and cache contract through its DSA indexer. DeepSeek V4.1 Flash 1017 is an encoder-decoder with Engram memory, not a 0731 weight update. Mistral Large 4 is a trillion-parameter-class MLA/indexer MoE whose FP8 export fills the node. Muse Glimmer is a dense 30B whose two KV heads limit tensor-parallel sharding. These are different memory and scheduling problems, not twelve names for the same Transformer.

## There is no defensible universal winner yet

A useful comparison fixes the task distribution, prompt/output lengths, quality threshold, reasoning settings and latency objective. Compare per-node goodput for capacity planning and per-request latency for interactivity. Do not rank engines by unrelated benchmark rows from B200, GB300, RTX Blackwell and an unspecified B300 OEM node.

Choose a starting engine using evidence of the exact checkpoint path within the **required KServe infrastructure**. Promote a candidate only after correctness and workload tests. Compare vLLM and SGLang through the intended KServe service path, accounting for each runtime's command, readiness, metrics and routing integration. Advanced disaggregation and routing require engine-specific integrations. [KSRT](https://kserve.github.io/website/docs/model-serving/generative-inference/overview) [KSLLM](https://kserve.github.io/website/docs/model-serving/generative-inference/llmisvc/llmisvc-overview)

## Suggested workload portfolios

For short interactive chat, prioritize first-content latency and stable output pacing; include target-only baselines because drafting is not free. For coding agents, preserve multi-turn reasoning/tool serialization and measure actual draft acceptance. For long documents, constrain context and concurrency explicitly and measure retrieval quality. For multimodal tasks, include image preprocessing/encoder time and enforce input limits. For high-volume endpoints, compare independent small-model replicas against wider TP groups at equal node occupancy.

The [optimization guide](optimization.md) explains the mechanisms and workload tradeoffs behind these choices.
