## Release migration under KServe

- **KV memory sizing changes with the same command line.** The extensible cache commits a small allocation, captures graphs and warms up, then grows the cache using measured free memory with headroom for transients and fragmentation. When utilization is unspecified it resolves to 1.0 with extensible sizing and 0.92 without it. An explicit utilization caps the instance and can coexist with extensible sizing. Fixed cache bytes, an explicit block-count override, elastic EP or incompatible connector memory access can preclude extensible sizing. On CUDA, a connector requesting fabric handles can also disable automatic selection if IMEX is unavailable. Check actual blocks, peak memory per rank, preemptions and decode latency for the configured KServe replica. Greater cache capacity can admit more work and increase inter-token latency at saturation. [V034-CACHE](https://raw.githubusercontent.com/vllm-project/vllm/62d4bc3c7e33b1b6c906e233e6af2d3506c482ca/vllm/config/cache.py) [V034-CACHE-RESOLVE](https://raw.githubusercontent.com/vllm-project/vllm/62d4bc3c7e33b1b6c906e233e6af2d3506c482ca/vllm/config/vllm.py) [V034-EXTENSIBLE](https://raw.githubusercontent.com/vllm-project/vllm/62d4bc3c7e33b1b6c906e233e6af2d3506c482ca/vllm/v1/worker/extensible_kv_cache.py)
- **Block size and model runner.** The general cache block default moves from 16 to 64. A model, cache group or backend can require another alignment or kernel page size. To isolate the version change, hold block size and explicit memory limits fixed where both releases support them, then compare release defaults separately. Model Runner V2 is the only GPU runner. The V1 opt-out fails at startup. Port V1-only logits processors and check the runtime image’s CUDA/driver compatibility before interpreting startup failures as model failures. [V034-PRIOR-CACHE](https://raw.githubusercontent.com/vllm-project/vllm/4ba787ec9959e566d3b587a796dff07673324da5/vllm/config/cache.py) [V034-CACHE](https://raw.githubusercontent.com/vllm-project/vllm/62d4bc3c7e33b1b6c906e233e6af2d3506c482ca/vllm/config/cache.py) [V034-RELEASE](https://api.github.com/repos/vllm-project/vllm/releases/tags/v0.34.0) [V034-FA-UTIL](https://raw.githubusercontent.com/vllm-project/vllm/62d4bc3c7e33b1b6c906e233e6af2d3506c482ca/vllm/v1/attention/backends/fa_utils.py)
- **Speculation and routing.** Draft cache dtype inheritance and FULL-graph fixes can change acceptance, memory and timing with identical arguments. Record target and draft revisions, resolved cache dtype, proposal count and naturally accepted tokens. Cache-aware admission is opt-in. Best-effort NUMA binding is now a default. Record the runtime pod’s CPU/NUMA placement before attributing a latency change to the engine or checkpoint. Where P/D uses a KV connector, include the connector and transport in the comparison.
