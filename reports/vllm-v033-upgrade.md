**Source review: November 6, 2026 (UTC).** vLLM v0.33.0 is the latest stable release. First comparison: change only the engine image (v0.32.0 → v0.33.0) while retaining model revision, tokenizer, draft, topology, explicit precision and workload. Several defaults changed (GLM-5.3-Flash KV dtype, lookahead block hashes, and, for Qwen GDN models with prefix caching, the FlashInfer prefill checkpoint grid that sets the Mamba block size), so pin those explicitly in both arms where a flag exists and record the resolved values from the startup log.

## Two-pass review

1. **Source support.** Release identity, tag objects and the commit were read from the GitHub API. Every PR cited as in v0.33.0 appears in the release body; for the Gemma, Qwen GDN and PLE items, compare calls confirm the merge commits are ancestors of `4ba787ec`. #59986, #62729 and #64650 are merged on main but absent from `4ba787ec`. #61530, #61869, #62189 and #62769 are open. The specialized-decode gate, fp8 → `fp8_ds_mla` rewrite, DSpark block-size defaulting, Rust-frontend default, watchdog default, encoder-graph default, GDN prefill backend selection and CUDA pins were read in source at `4ba787ec`.
2. **Challenge.** All throughput and latency figures are author claims on GB300, GB200, B200, H200, RTX 5090 or B300 in other configurations; none was reproduced, and none transfers to a different TP, concurrency or checkpoint. The GDN and PLE checkpoint changes were validated upstream on SM100 only, and the Gemma encoder-graph fixes apply only with an opt-in setting. The recipe's DeepSeek V4.1 B300 rows were measured on 0909 weights with a `cu134` nightly image, not a release image. Whether the B300 driver supports CUDA 13.0, whether NVLink multicast is available for the specialized decode, and whether Prometheus metric names changed (no full `/metrics` diff was run) remain open.
