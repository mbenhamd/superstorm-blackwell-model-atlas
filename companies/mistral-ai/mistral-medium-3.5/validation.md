## Decision and applicability

**Proposed experiments; no GPU results.** Determine how much tensor sharding this dense 128B service needs for its actual context, image and concurrency distribution, then assess speculation. Full-history GQA across 88 layers makes context/concurrency memory a central constraint. The current publisher card/config matched the atlas pin when retrieved again on 2026-10-15 UTC. The corrected Transformers config contains `mscale_all_dim=0.0`; an old derivative or a loader that interprets another layout incorrectly can invalidate long-context results. [mistral-medium-3.5-CFG](https://huggingface.co/mistralai/Mistral-Medium-3.5-128B/raw/22b2b868a15677cfa6061277ed2f653d1349a9ab/config.json), [mistral-medium-3.5-FIXCFG](https://huggingface.co/mistralai/Mistral-Medium-3.5-128B/commit/c4be198050fb5789774a55b92ed697becfbf20ae).

Start with the [publisher-derived vLLM TP8 baseline](../../../profiles/mistral-medium-3.5.fp8.vllm.baseline.json). The [TP2 probe](../../../profiles/mistral-medium-3.5.fp8.vllm.tp2-probe.json) and [SGLang TP8 probe](../../../profiles/mistral-medium-3.5.fp8.sglang.baseline.json) must qualify before comparison. Both probe profiles omit reasoning/tool parser flags: use an explicitly pinned and validated parser configuration for those tasks. The single audited target export is static FP8 with higher-precision exclusions; there is no audited BF16/NVFP4 comparison in this atlas. Dequantizing these files does not create an original BF16 quality reference. [precision](precision.md), [serving](serving.md).

All three profiles cap total context at 32,768 and active requests at 32. Begin with 4K/16K serialized inputs and 128/1,024 output budgets at concurrency 1 and 8; count image/template tokens and reserve room for generation. Increase active count only within measured headroom. A 32K input plus output, 128K contexts or larger queues need a separately qualified configuration. Reasoning-quality evaluation may need a larger declared output budget than the short service probe; report truncation rather than scoring a cut-off answer as completed reasoning.

## Architecture and serving experiments

| ID / hypothesis | Controlled experiment | Evidence and decision |
| --- | --- | --- |
| M35-01 — The loader applies the correct artifact and positional configuration. | Qualify the pinned static-FP8 target at TP8, recording checkpoint layout, tokenizer/encoding dependencies and loaded positional values. Check higher-precision vision/projector/head exclusions and actual kernels. If comparing consolidated and Transformers layouts, treat them as separate loader experiments with the same model revision and workload. | Retain config/parameter-file hashes, resolved YaRN settings, selected weight-file manifest, startup/read/repack/compile times and memory. Verify short and long reference tasks before speed. Equal index byte totals do not prove tensor equality; never add both alternative layouts as one resident model. An unresolved positional mapping or unintended loader fallback blocks comparison. |
| M35-02 — Longer context and more requests fit while preserving useful accuracy. | With KV dtype fixed, sweep feasible lengths at fixed concurrency, then active requests at fixed length. After the 32K-cap baseline, qualify separate caps for longer buckets, including 128K if required. Place facts at early/middle/late positions and add distractors/multi-hop questions. Repeat after eviction, cancellation and chunked prefill where supported. | Report task-by-length/position accuracy, KV occupancy, per-GPU peak/headroom, TTFT, TPOT and allocation failures. The [11 GiB ideal BF16 KV payload at 32,768 tokens](architecture.md) is a calculation across the model, not a measured per-GPU reservation. Later FP8-KV testing changes a separate variable and repeats the quality gate. |
| M35-03 — Less sharding creates more useful node capacity. | After the TP8 reference qualifies, compare one TP8 group, two TP4 groups and four TP2 groups on eight GPUs. Admit eight TP1 replicas only after a constrained TP1 workload loads and passes memory/quality gates. Freeze target revision, KV dtype, input distribution, offered load, routing affinity and CPU budget. Fix total-node admission and a declared batch-token budget policy with explicit per-group values before separate capacity tuning. | Report whole-node goodput and request tails, plus single-group latency, communication time and memory. Log effective batching/scheduler settings; unmatched budgets require a complete-configuration comparison. Retain rejected/OOM runs. A TP1 weight-fit calculation cannot justify long-context concurrency; an idle extra GPU does not count as an equal-resource result. This dense model does not supply an MoE expert-parallel axis. |
| M35-04 — Reasoning and tools remain correct through the Mistral protocol. | Qualify tokenizer/encoding, reasoning parser and tool parser on each engine. Freeze `reasoning_effort=none` or `high` and the mode's full sampling policy within A/B runs. Separately compare policies on the same tasks, including no-call, single/multiple calls, multi-turn tool feedback and streaming cancellation. | Save raw/parsed responses and tool traces. Report final-answer/task success, first-answer latency, reasoning/final tokens and retries. A missing parser or malformed call is a protocol failure; a valid wrong call is a quality failure. Task completion time, including retries, decides whether higher reasoning effort helps. |
| M35-05 — Image processing survives batch and topology changes. | Freeze image bytes, processor, resizing/cropping and image order. Compare text-only, one-image and multi-image traces; vary aspect ratio/resolution separately. Repeat the same text with changed images and cancel during image prefill. Qualify each image path before including it in mixed traffic. | Record image/visual-token counts, preprocessing/encoder cost where exposed, memory peaks, answer quality and TTFT. Reject wrong-image reuse, ordering errors or silent dropping. Text/image input support does not establish a video or audio endpoint; neither is part of this plan. |
| M35-06 — A matching EAGLE drafter reduces useful latency after its costs. | Only after the target passes the earlier gates, qualify publisher drafter `mistralai/Mistral-Medium-3.5-128B-EAGLE` at `d31694b0f55b51d4d962b5c3dbf0e03d1f019275` with the pinned target and build. Compare speculation off/on in that same build/topology, initially within the atlas's 32K cap, then supported depth settings and load levels. | Record draft/target identities, draft/verification work, natural acceptance distribution/denominator, additional memory, task quality and latency/goodput. Include rejected proposals, cancellation and tool boundaries. Qualify image-conditioned generation separately. The drafter has a native `params.json`/consolidated layout; a failed `config.json` fetch is not evidence of a missing model. No existing atlas profile enables it. |

The TP8 profile explicitly sets `--max-num-batched-tokens 16384`; the TP2 probe omits this option. Resolve the effective default and record the chosen per-group and aggregate budget policy before attributing a result to topology.

The publisher's [EAGLE card](https://huggingface.co/mistralai/Mistral-Medium-3.5-128B-EAGLE/raw/d31694b0f55b51d4d962b5c3dbf0e03d1f019275/README.md) documents vLLM and SGLang recipes. Its [native parameters](https://huggingface.co/mistralai/Mistral-Medium-3.5-128B-EAGLE/raw/d31694b0f55b51d4d962b5c3dbf0e03d1f019275/params.json) are metadata evidence, not a qualified loader or runtime measurement. The vLLM example gives the draft a 65,536-token cap; it does not establish speculation over the target's full native window. Resolve an immutable build and its actual target/draft limits before extending this experiment. Historical nightly instructions and mutable image tags are not tested current binaries. Source IDs: `mistral-medium-3.5-EAGLE-CARD`, `mistral-medium-3.5-EAGLE-PARAMS`.

## Quality tasks chosen for this model

| Task and primary source | Why it belongs here / controls and outputs |
| --- | --- |
| [RULER v1](https://github.com/NVIDIA/RULER/tree/rulerv1-ns) — MBENCH-RULER-V1 | Use fixed retrieval, tracing and aggregation tasks to expose long-context regressions near the corrected YaRN path. Pin the driver, linked NeMo-Skills implementation, tokenizer and generated samples; report per-task/length accuracy. Add held-out long-document questions with cited evidence spans because synthetic recall does not establish document reasoning. |
| [LiveCodeBench](https://github.com/LiveCodeBench/LiveCodeBench) — MBENCH-LCB | Use a frozen release/date window for executable code-generation quality and natural EAGLE acceptance. Pin prompt adapter, sample count and evaluator resource/time limits; report pass@1, failure categories and truncations. Keep this endpoint evaluation separate from a multi-step coding agent. |
| [SWE-bench Verified](https://www.swebench.com/SWE-bench/) — MBENCH-SWE | Add this only when repository work is the application: it evaluates patches against real issues with an official containerized harness. Pin task IDs, agent/tool scaffold, repository/test images, turn/token/time budgets and retries. Report resolved tasks, model/tool time and total task cost. A screening subset is not the full Verified score. |
| [BFCL](https://github.com/ShishirPatil/gorilla/tree/main/berkeley-function-call-leaderboard) — MBENCH-BFCL | Offline function-selection/argument and multi-turn categories check the Mistral parser and agent contract together. Pin the handler/tool environment and score semantic correctness separately from valid JSON. Web-search categories introduce an external environment and require their own frozen experiment. |
| [MMMU-Pro](https://github.com/MMMU-Benchmark/MMMU/tree/main/mmmu-pro) — MBENCH-MMMUPRO | Select one fixed standard or vision setting to evaluate image-conditioned reasoning across TP/engine/speculation changes. Preserve image-placeholder mappings; report per-subject accuracy and malformed outputs. Add held-out document/image questions matching the application's sizes and languages. |
| Held-out instruction and multilingual tasks | Use fixed rubrics or programmatic checks for required fields, forbidden extra text, answer correctness and tool-result use in the actual languages. Evaluate `none` and `high` separately. These tasks test the deployed service's obligations rather than assuming that a coding score establishes general instruction quality. |

The publisher reports agent benchmark results under its own conditions. Those claims motivate the optional agent evaluation; they do not set a local B300 quality floor or imply the same outcome with another scaffold. Token throughput from a replayed prompt trace measures the engine; SWE-bench completion includes repository/test/tool work and must carry those resources and costs. Freeze quality item IDs before tuning, keep a held-out final set and retain failures. [mistral-medium-3.5-CARD](https://huggingface.co/mistralai/Mistral-Medium-3.5-128B/raw/22b2b868a15677cfa6061277ed2f653d1349a9ab/README.md).

## Run record and promotion

Follow the [shared model benchmark guide](../../../benchmarks/MODEL-BENCHMARKS.md), [protocol](../../../benchmarks/PROTOCOL.md) and [experiment manifest](../../../benchmarks/experiment.template.json). Declare quality floors/regression limits, latency/error budgets, useful goodput improvement, memory reserve and analysis method before the campaign. Unknown thresholds block promotion. Randomize order and repeat paired A/B runs; an improvement interval crossing the declared useful threshold is inconclusive. Stable-versus-nightly comparisons need distinct artifacts, while speculation off/on needs the same build.

Deliver raw outputs and item scores, complete task/tool traces where applicable, tokenizer/parser/config hashes, weight-layout manifest, effective kernel/KV diagnostics, memory and cancellation evidence, and a decision per workload/mode. The [HTTP/SSE result schema](../../../benchmarks/result.schema.json) cannot certify semantic tool correctness, image quality, code execution or agent completion. These plans do not change the existing profiles' candidate/probe status, and no benchmark result is currently measured.
