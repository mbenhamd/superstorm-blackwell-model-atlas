## Interpretation

The default export uses static-activation FP8 without the 128×128 weight-block scheme used by several other models in the list. Vision, projector and language-head exclusions remain higher precision. Do not force a block-FP8 loader or an NVFP4 mode onto the publisher files; the NVFP4 variant below is a separate exported artifact.

The description “FP8-ish” is too imprecise for this artifact. Fresh inspection on 2026-10-16 confirms `quant_method: fp8`, `activation_scheme: static`, `weight_block_size: null` and `dequantize: false` in the pinned Transformers config; native `params.json` declares `fp8_e4m3` weights with a `TENSOR` activation scheme. A root `dtype: bfloat16`, or the SGLang EAGLE recipe's `--dtype bfloat16`, does not turn these serialized FP8 weights into an original BF16 checkpoint. [mistral-medium-3.5-CFG](https://huggingface.co/mistralai/Mistral-Medium-3.5-128B/raw/22b2b868a15677cfa6061277ed2f653d1349a9ab/config.json), [RR-GM-MISTRAL-PARAMS](https://huggingface.co/mistralai/Mistral-Medium-3.5-128B/raw/22b2b868a15677cfa6061277ed2f653d1349a9ab/params.json).

The matching EAGLE artifact is `mistralai/Mistral-Medium-3.5-128B-EAGLE` at `d31694b0f55b51d4d962b5c3dbf0e03d1f019275`. Its native parameters likewise declare FP8 e4m3 and tensor activation scaling, with two GQA layers and no vision encoder. Its single listed `consolidated.safetensors` is 3,070,358,348 bytes including the header. Neither this file size nor a cookbook memory estimate measures runtime draft overhead, shared buffers or verification workspace. [mistral-medium-3.5-EAGLE-PARAMS](https://huggingface.co/mistralai/Mistral-Medium-3.5-128B-EAGLE/raw/d31694b0f55b51d4d962b5c3dbf0e03d1f019275/params.json), [mistral-medium-3.5-EAGLE-TREE](https://huggingface.co/api/models/mistralai/Mistral-Medium-3.5-128B-EAGLE/tree/d31694b0f55b51d4d962b5c3dbf0e03d1f019275?recursive=false&expand=false).

## NVFP4 variant (NVIDIA export)

**`nvidia/Mistral-Medium-3.5-128B-NVFP4` @ `b8c66d2098edd8c9c26bde2b2ff41b5967e111ae`** is an exporter derivative, not a publisher checkpoint (created 2026-06-30, last commit 2026-07-01; promoted to catalog variant `nvfp4` on 2026-11-06). Its `quantization_config` (identical in `config.json` and `hf_quant_config.json`) is ModelOpt `MIXED_PRECISION` with 616 `quantized_layers`: 249 `NVFP4` (group 16) entries for `gate/up/down` in layers 4–86 and 367 `FP8` entries for `q/k/v/o` in all 88 layers and `gate/up/down` in layers 0–3 and 87; `ignore: []`; `kv_cache_scheme` FP8 static. Unlisted modules (vision tower, projector, embedding, `lm_head`) are BF16. The corrected YaRN `mscale_all_dim: 0.0` is retained. [mistral-medium-3.5-NV-NVFP4-CFG](https://huggingface.co/nvidia/Mistral-Medium-3.5-128B-NVFP4/raw/b8c66d2098edd8c9c26bde2b2ff41b5967e111ae/config.json) [mistral-medium-3.5-NV-NVFP4-HFQ](https://huggingface.co/nvidia/Mistral-Medium-3.5-128B-NVFP4/raw/b8c66d2098edd8c9c26bde2b2ff41b5967e111ae/hf_quant_config.json)

Header census of all 10 shards (HTTP range reads only): U8 43,864,031,232 B (packed FP4), F8_E4M3 39,557,529,600 B (FP8 weights and FP4 group scales), BF16 11,803,244,032 B, F32 8,096 B; total 95,224,812,960 B, equal to the index and 0.713× the publisher FP8 HF-layout index (133,605,834,656 B). By component: NVFP4 MLP 49.35 GB, FP8 attention 28.79 GB, FP8 edge MLP 5.28 GB, vision 4.99 GB, embedding 3.22 GB, head 3.22 GB, projector 0.37 GB. Each quantized linear stores both `activation_scale` and `input_scale`; engines rename the first onto the second, so their equality (unchecked) matters. Serialized bytes are not resident memory; per-GPU weights and KV room are in the [dossier](nvfp4.md#5-memory-weights-per-gpu-and-kv-room). [mistral-medium-3.5-NV-NVFP4-INDEX](https://huggingface.co/nvidia/Mistral-Medium-3.5-128B-NVFP4/raw/b8c66d2098edd8c9c26bde2b2ff41b5967e111ae/model.safetensors.index.json) [mistral-medium-3.5-NV-NVFP4-HEADERS](https://huggingface.co/nvidia/Mistral-Medium-3.5-128B-NVFP4/tree/b8c66d2098edd8c9c26bde2b2ff41b5967e111ae)

Contract hazards in the export's own files: `params.json` is byte-identical to the publisher's FP8 `params.json` and does not describe the NVFP4 tensors, so the Mistral-native config path must not be used; the export ships a `chat_template.jinja` that differs from the publisher's (empty default system message); the card states "nvidia-modelopt v0.44.0" while both quantization files record producer `modelopt` 0.37.0. [mistral-medium-3.5-NV-NVFP4-PARAMS](https://huggingface.co/nvidia/Mistral-Medium-3.5-128B-NVFP4/raw/b8c66d2098edd8c9c26bde2b2ff41b5967e111ae/params.json) [mistral-medium-3.5-NV-NVFP4-CHAT-TEMPLATE](https://huggingface.co/nvidia/Mistral-Medium-3.5-128B-NVFP4/raw/b8c66d2098edd8c9c26bde2b2ff41b5967e111ae/chat_template.jinja)

Scope limits: the exporter validated `vllm/vllm-openai:v0.21.0` at TP4 on B200; its FP8-versus-NVFP4 accuracy table (seven tasks, sampled decoding, no repeat counts) is an exporter claim, not reproduced. vLLM v0.33.0 loads the precision contract by source reading; SGLang v0.5.23 does not (fused `qkv_proj`/`gate_up_proj` are not resolved for Mistral3), see the [dossier](nvfp4.md#3-support-at-the-stable-releases). The official EAGLE card names only the FP8 target, so EAGLE acceptance with this export is unestablished. [mistral-medium-3.5-NV-NVFP4-CARD](https://huggingface.co/nvidia/Mistral-Medium-3.5-128B-NVFP4/raw/b8c66d2098edd8c9c26bde2b2ff41b5967e111ae/README.md)

A conversion of the publisher checkpoint by other tooling must begin from the corrected configuration and validate long-context and multimodal behavior.

## Deployment rule

Pin the model revision, tokenizer/processor revision, quantization configuration, runtime commit and image digest together. A root BF16 `dtype` can coexist with quantized weights. The real contract includes serialized tensor types, scales, grouping, excluded modules, activation precision and runtime repacking. Do not cast a quantized checkpoint to BF16 and call it the original BF16 reference.

For every candidate, compare target-only quality against the appropriate reference before enabling lower-precision KV or speculation. [Precision analysis](../../../reports/precision-and-kernels.md) distinguishes NVFP4, MXFP4, FP8 and BF16. [NV4](https://developer.nvidia.com/blog/introducing-nvfp4-for-efficient-and-accurate-low-precision-inference/) [TE](https://docs.nvidia.com/deeplearning/transformer-engine/examples/fp8_primer.html)
