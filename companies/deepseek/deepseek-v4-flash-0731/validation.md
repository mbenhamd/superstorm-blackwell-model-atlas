## What needs a decision

Determine whether the exact July-31 release serves the application's coding, tool and long-document work correctly, and whether a larger GPU group, a smaller indexer cache or DSpark improves useful capacity. The earlier sweep did not specify encoding checks, a long-context scorer or an equal-node comparison. This plan makes those controls explicit. Use the [shared benchmark selection guide](../../../benchmarks/MODEL-BENCHMARKS.md), [protocol](../../../benchmarks/PROTOCOL.md) and [experiment record](../../../benchmarks/experiment.template.json) for the common evaluation contract and decision rules.

## Choose scored workloads for 0731

| Suite / proposed use | Why it is useful here | Scoring and controls |
| --- | --- | --- |

Report pass@1 under that policy, failures and truncation, with reasoning/output counts. Use the common endpoint adapter or official custom-output scoring, not a harness launch that silently changes topology. Public problem dates do not establish absence from training. [MB-LIVECODEBENCH](https://raw.githubusercontent.com/LiveCodeBench/LiveCodeBench/28fef95ea8c9f7a547c8329f2cd3d32b92c1fa24/README.md) |

Selected-category results are not a complete BFCL score. [MB-BFCL](https://raw.githubusercontent.com/ShishirPatil/gorilla/6ea57973c7a6097fd7c5915698c54c17c5b1b6c8/berkeley-function-call-leaderboard/README.md) |
| RULER v1 and held-out document questions with answer/evidence labels | The 128-token recent window, compressed history and sparse index make “a long request was accepted” an inadequate accuracy check. | Use the cited `rulerv1-ns` pipeline and pin its NeMo-Skills dependency. Freeze generated examples/seeds with the 0731 tokenizer; report each task/length separately. Add multiple relevant passages, distractors, absent answers and evidence at different distances from the query. Do not equate synthetic retrieval with document reasoning. [MB-RULER-V1](https://raw.githubusercontent.com/NVIDIA/RULER/e8bbff677ca2c239640dc90f93310dcf32408c93/README.md) |
| Application instruction and multilingual fixtures, optionally IFEval from the shared guide | A mean coding score can miss schema, language or formatting regressions critical to the service. | Freeze rubrics and exact validators; report each critical stratum. Keep these application scores separate from public benchmark aggregates. The native 0731 artifact is a text model; the separate Flash Vision checkpoint needs another qualification campaign. |

Before any of those scores, run encoding round trips for plain chat, thinking and multi-turn tools. Compare the actual serialized token sequence with the pinned helper for the same messages. Cover string versus JSON-valued tool arguments, parallel call/result ordering, streamed delimiter fragments, EOS and stop handling. The reference helper drops some earlier thinking in ordinary chat by default but retains it when tools are supplied; verify the chosen policy instead of borrowing Kimi's rule. `reasoning_effort` has no effect in the reference chat mode. Treat malformed output as a recorded failure; the publisher parser does not promise to repair it. [deepseek-v4-flash-0731-ENC](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash-0731/blob/7872f01b1d1fe23eabc4c98b48bffcef5a386062/encoding/README.md).

## Run the experiments in this order

| ID | Controlled experiment and mechanism | Required observations and decision |
| --- | --- | --- |
| D01 — exact target and protocol | Qualify target-only on the four-GPU vLLM baseline and SGLang TP4 control. Start with short requests and low load, then run the scored suites. | Save load/repacking/graph memory, actual kernels, effective C4/C128 state dtype/pool capacities and all encoding/parser settings. Compare to the publisher reference on supported diagnostic cases; use declared numerical tolerances if logits are available, and scored outcomes otherwise. Stop before timing on unexplained fallback, invalid outputs or tool/reasoning boundary failures. |
| D02 — compressed history and indexer precision | With target-only and topology fixed, compare the qualified default/higher-precision indexer cache with the supported FP4 indexer path. Hold MLA KV and C4/C128 compressed-state dtype fixed; vary each only in a separately qualified experiment. | Log the **effective** indexer representation, attention backend and memory pools. Score long-context tasks and move evidence across the 128-token recent-window boundary and the installed cache-page boundaries. Include chunked prefill, prefix reuse, eviction and cancellation. A lower memory figure is insufficient if retrieval or answer quality regresses. |
| D03 — four versus eight GPUs | First measure one qualified four-GPU group. Then compare one DP8+EP group with two independent DP4+EP groups on the same eight-GPU node, if both qualify. Evaluate SGLang TP4/TP8 and two TP4 groups as separate qualified candidates. | Hold aggregate admission/concurrency and prefix-routing policy fixed for the first comparison; tune separately. Record per-group queues, all GPU/CPU resources, per-rank memory and expert/communication imbalance. Report whole-node goodput and tails under the same offered workload. A four-versus-eight scaling result alone cannot rank equal-cost deployments. |
| D04 — natural DSpark | On the same qualified topology/cache settings, compare no DSpark with the engine's documented DSpark default. SGLang starts at five proposals; its documented downward sweep is 1–5. vLLM's recipe starts at seven; vary supported proposal counts separately. | Record proposed, accepted and emitted tokens, draft/verify time, graphs and memory, queueing, final-answer latency and quality. Exercise accepted/rejected blocks, stop/EOS inside a block, cancellation, cache churn and the next session. No simulated acceptance. Do not equate the checkpoint's block size, CLI proposal count and tokens emitted after verification. |
| D05 — effort and output budget | Within a qualified serving configuration, compare application-selected low/high/max reasoning budgets on the same tasks; keep those settings fixed for engine A/B. | Score useful final answers and record first-final-answer latency, generated reasoning/answer tokens, output-limit finishes and elapsed time. Treat short-budget results as budget-constrained measurements, not reproductions of the publisher's high/max evaluation. |
| D06 — scheduling under mixed load | Replay short chat/tools, long documents and long coding generations. Vary one supported admission, prefill-chunk or graph setting, then confirm the selected combination. | Measure offered/completed/scored requests, queue delay, TTFT, first-answer/end-to-end tails, failures and node goodput. Repeat with cache eviction and burst recovery. Retain all failed runs and check that the client or tool harness is not the bottleneck. |

The recipe's FP4 indexer cache is a separate option from native FP4 expert storage. Inspect the installed build's actual flag and default before D02; omitting a flag is not evidence that an optimization is off. If changing precision also changes a kernel, label the result as that paired change. Do not transplant sparse-attention optimizations for another DeepSeek release without exact 0731 evidence. [deepseek-v4-flash-0731-VR](https://recipes.vllm.ai/deepseek-ai/DeepSeek-V4-Flash?features=tool_calling,reasoning&hardware=b300).

The SGLang family cookbook separately documents `SGLANG_DSV4_COMPRESS_STATE_DTYPE` for C4/C128 state pools: it describes FP32 as the default and a BF16 offline-compression option that can change automatic pool capacity. Its example names the earlier `DeepSeek-V4-Flash`, so this is a reason to inspect and record the exact 0731 build's effective state dtype, not evidence that the BF16 option qualifies for 0731. Qualify that path separately before a state-precision experiment and keep allocated capacity fixed before testing any capacity gain. [deepseek-v4-flash-0731-GR](https://docs.sglang.io/cookbook/autoregressive/DeepSeek/DeepSeek-V4).

For D04, the publisher vLLM example uses greedy drafting while the local recipe/profile uses probabilistic drafting. Keep client sampling fixed and record the draft sampling/rejection policy; these are different candidate configurations. SGLang's documented default verifies six positions for five proposals. Start from the documented settings and qualify changes; do not modify model config to make the numbers match. [Publisher card](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash-0731/blob/7872f01b1d1fe23eabc4c98b48bffcef5a386062/README.md), [SGLang DSpark guidance](https://docs.sglang.io/cookbook/autoregressive/DeepSeek/DeepSeek-V4#3-4-dspark-speculative-decoding).

### Length and load are constrained experiments

Start with 4K/16K/32K serialized inputs, concurrency 1 and 8, then 32 and a fixed offered-rate ladder around saturation. Here K means 1,024 tokens. Include a near-cap bucket only after reserving generation, tool schema and history tokens inside the 65,536-token profile limit. A 64K input with any output is infeasible in these profiles. Raising the cap for 64K/128K inputs requires a separate load/memory/quality pass; the configured 1M positional ceiling is not a capacity result.

Short 128/1,024-token output caps are useful for shape diagnostics, but may censor reasoning before an answer. For scored quality, choose the budget using a separate pilot and record truncated or missing-final-answer cases rather than discarding them. The publisher recommends up to 384K output for high/max effort; that cannot fit the local cap, and any long-output arm must reserve the prompt in addition to output. Report application budget results as such. The publisher's sampling guidance also differs between agentic and other work, so freeze the selected policy for every A/B comparison. [Usage guidance](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash-0731/blob/7872f01b1d1fe23eabc4c98b48bffcef5a386062/README.md).

## Produce a decision with its limits

The base card's code-agent results use the publisher's named harness and max-effort settings; the card describes that harness as pending release. Its internal DSBench scores are not reproducible local acceptance gates. The SGLang four-GB300 example establishes an upstream configuration report, not a measurement on this B300 node. The unresolved 284B-versus-304B accounting must not be used as a substitute for loaded tensor bytes or measured memory. [Publisher card](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash-0731/blob/7872f01b1d1fe23eabc4c98b48bffcef5a386062/README.md), [architecture accounting](architecture.md).

For every candidate, retain exact model/build/encoding identities, benchmark/adapter/scorer manifests, raw answers and tool traces, per-item scores, paired uncertainty, truncation/error counts, cache/acceptance diagnostics, per-rank peak memory and whole-node latency/goodput. Join task success and timing by request ID if reporting quality-adjusted goodput. The atlas streaming probe does not save answers or run a tool loop and cannot supply that evaluation by itself.

Promote only when predeclared critical-task quality margins and service objectives pass across repeated runs. Reject demonstrated correctness or service regressions, mark missing support/adapter requirements blocked, and mark insufficient evidence inconclusive. There is no invented SLA, score target or “fastest engine” conclusion in this plan.
