## Interpretation

Moonshot describes MXFP4/MXFP8 quantization-aware training. The serialized config specifies MXFP4 groups of 32 and lists excluded modules; it leaves `input_activations` unset. That training description does not prove that every module or serving backend runs MXFP8 activations. NVIDIA describes BF16 attention in the original checkpoint. [Base card](https://huggingface.co/moonshotai/Kimi-K3/blob/f831ab66814297da540d832a5235f8e904f29d06/README.md), [base config](https://huggingface.co/moonshotai/Kimi-K3/raw/f831ab66814297da540d832a5235f8e904f29d06/config.json), [NVIDIA card](https://huggingface.co/nvidia/Kimi-K3-NVFP4/blob/b2428a0b83a8b712ff2e1a8448a103d4175341f1/README.md).

The derivative's config declares ModelOpt `MIXED_PRECISION`: expert weight/activation groups of 16 and separate `FP8_PB_WO` attention entries. NVIDIA reports an approximately 1.6 TB download. Download size is not resident GPU memory; scales, runtime repacking, caches and temporary allocations require separate accounting. [Derivative config](https://huggingface.co/nvidia/Kimi-K3-NVFP4/raw/b2428a0b83a8b712ff2e1a8448a103d4175341f1/config.json), [NVIDIA card](https://huggingface.co/nvidia/Kimi-K3-NVFP4/blob/b2428a0b83a8b712ff2e1a8448a103d4175341f1/README.md).

The immutable safetensors indexes provide a more precise **serialized tensor-byte** reference. Only their metadata prefixes were retrieved; this is not a complete tensor census or a resident-memory measurement.

[Native index](https://huggingface.co/moonshotai/Kimi-K3/resolve/f831ab66814297da540d832a5235f8e904f29d06/model.safetensors.index.json), [NVIDIA index](https://huggingface.co/nvidia/Kimi-K3-NVFP4/resolve/b2428a0b83a8b712ff2e1a8448a103d4175341f1/model.safetensors.index.json). The approximately 1,450 GiB figure is close to the native index total; it does not establish NVIDIA-export residency. Against **2,304 decimal GB**, subtracting these index totals leaves about **743 GB native / 694 GB NVIDIA**, before runtime allocations. These are bookkeeping differences, not available KV budgets. Subtracting a GiB figure directly from decimal GB produces the misleading approximately 850 GB estimate. Actual per-rank weights, state, graphs and communication buffers still determine capacity.

The export changes two important paths: routed experts and selected KDA/MLA attention projections. NVIDIA says it used no calibration dataset, set expert `input_scale=1.0`, and quantized attention weights into 128×128 FP8 blocks. A native-versus-NVFP4 quality change therefore cannot be attributed only to four-bit expert storage. The release-source SGLang path passes the checkpoint's SiTU constants into expert execution; its Blackwell native recipe selects FlashInfer MXFP4 W4A8 kernels. The NVIDIA export instead requires `flashinfer_trtllm`, including the appropriate SiTU scaling/finalization path. Automatic selection or `flashinfer_cutlass` is not an equivalent replacement for that export's documented recipe. [NVIDIA conversion and runtime instructions](https://huggingface.co/nvidia/Kimi-K3-NVFP4/blob/b2428a0b83a8b712ff2e1a8448a103d4175341f1/README.md), [SGLang recipe](https://docs.sglang.io/cookbook/autoregressive/Moonshotai/Kimi-K3), [immutable SGLang source](https://raw.githubusercontent.com/sgl-project/sglang/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/models/kimi_k3.py).

## Runtime evidence

SGLang PR #35077 merged on 2026-08-19 and is an ancestor of the v0.5.21 tag. Its author reports a correctness run on 8×GB300 and explicitly reports no speed measurement. Release-source inclusion is established; the exact installed wheel or image and its dependency stack have not been tested here. The current cookbook still points this export to the mutable `lmsysorg/sglang:dev-dev-kimi-k3-nvfp4` image. Do not repeat the older model card's blanket statement that pip SGLang cannot load it as a current release conclusion. [Compatibility PR](https://github.com/sgl-project/sglang/pull/35077), [release ancestry](https://github.com/sgl-project/sglang/compare/5f128395910dafb98c34083dc26cb790c7674d34...v0.5.21), [cookbook](https://docs.sglang.io/cookbook/autoregressive/Moonshotai/Kimi-K3).

NVIDIA's pinned card reports an older patched vLLM image on 8×B300. Its three historical PRs remain open, but **v0.31.0 already contains selected corresponding fixes**: mixed ModelOpt dispatch, KDA FP8 block alignment/replicated scales, MLA input-dtype handling and SiTU scaling. Open PR state is not proof those changes are absent. The exact mixed-export image remains unqualified here. [Q31-CAT-V031-VLLM-MODELS-KIMI-K3-NVIDIA-KDA-PY](https://raw.githubusercontent.com/vllm-project/vllm/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/models/kimi_k3/nvidia/kda.py) [Q31-CAT-V031-VLLM-MODELS-KIMI-K3-NVIDIA-MLA-PY](https://raw.githubusercontent.com/vllm-project/vllm/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/models/kimi_k3/nvidia/mla.py) [Q31-CAT-V031-VLLM-MODEL-EXECUTOR-LAYERS-FUSED-MOE-EXPERTS-TRTLLM-NVFP4-MOE-PY](https://raw.githubusercontent.com/vllm-project/vllm/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/layers/fused_moe/experts/trtllm_nvfp4_moe.py)

**Do not apply the old publisher patch unchanged to v0.31.0.** It imports `ModelOptFp8PbWoLinearMethod`, which the refactored release module does not define. Preserve the publisher's old image+patch as its own artifact identity; qualify the built-in release path separately. The mixed payload is approximately 3.13% larger than native MXFP4, so it does not establish a memory-saving argument over that base. [Q31-CAT-KIMI-NV-SITECUSTOMIZE-PY](https://huggingface.co/nvidia/Kimi-K3-NVFP4/raw/b2428a0b83a8b712ff2e1a8448a103d4175341f1/runtime_patches/sitecustomize.py) [ATTQ-V-MODELOPT-STABLE](https://raw.githubusercontent.com/vllm-project/vllm/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/layers/quantization/modelopt.py) [TOPK-BASE-INDEX-RANGE](https://huggingface.co/moonshotai/Kimi-K3/resolve/f831ab66814297da540d832a5235f8e904f29d06/model.safetensors.index.json) [TOPK-NV-INDEX-RANGE](https://huggingface.co/nvidia/Kimi-K3-NVFP4/resolve/b2428a0b83a8b712ff2e1a8448a103d4175341f1/model.safetensors.index.json)

## Deployment rule

Pin the target and tokenizer/processor revisions, quantization configuration, runtime commit, compatibility patch where used, and image digest together. Root BF16 metadata can coexist with quantized weights. Check serialized tensor types, scales, grouping, excluded modules, activation precision and runtime repacking; casting this checkpoint to BF16 does not reconstruct an original BF16 reference.

Compare target-only quality before changing KV precision or enabling speculation. The [precision analysis](../../../reports/precision-and-kernels.md) explains the formats; the [serving report](serving.md) describes the comparisons still needed.
